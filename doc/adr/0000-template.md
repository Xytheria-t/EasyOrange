# ADR 0000 — 架构决策记录模板（MADR 中文风格）

- **状态**：提议 / 接受 / 已替代 / 部分已替代
- **日期**：YYYY-MM-DD
- **决策者**：（可选）参与决策的角色或团队
- **标签**：（可选）`saga` `cqrs` `ai` `cache` 等便于检索的关键词

---

## 上下文（Context）

描述做出该决策时面临的背景、约束、问题陈述。回答以下问题：

- 我们要解决什么问题？
- 当前系统状态如何（已有模块、依赖、技术栈）？
- 有哪些强制约束（性能、合规、团队、外部依赖）？
- 不做任何事会怎样？

> 只陈述事实，不下结论。结论放「决策」节。

## 决策（Decision）

一句话明确写出我们选择什么。后续段落展开说明：

- 选择了什么方案
- 选择该方案的核心驱动力（驱动力应与「上下文」中的约束一一对应）
- 关键实现要点（如适用，引用项目代码位置）

代码引用示例：

- 实现：[OrderCommandHandler.java](../../easyorange-backend/easyorange-order/src/main/java/com/cartethyia/easyorange/order/application/command/OrderCommandHandler.java)

## 后果（Consequences）

### 正向后果

- 列出该方案带来的收益、能力、解耦效果等

### 负向后果

- 列出该方案引入的代价、风险、复杂度、技术债等

### 缓解措施

- 针对负向后果，已采取或计划采取的缓解手段

## 备选方案（Alternatives Considered）

逐一列出被拒绝的备选方案，并说明拒绝理由。每条包含：

- **方案名**：简述
- **拒绝理由**：与项目实际约束冲突的点、不可接受的代价

## 备注（Notes）

- 相关 ADR：（如 `Supersedes ADR-00XX`、`Related to ADR-00YY`）
- 相关文档：（链接到 `doc/架构/`、`doc/集成/`、`AGENTS.md` 等）
- 相关代码：（链接到关键类）
- 后续演进触发条件：（如某指标超过阈值时重新评估）
- 决策回顾周期：（可选，如半年复盘一次）

## 使用约定

1. **文件命名**：`NNNN-kebab-case-title.md`，`NNNN` 为四位递增序号，从 `0001` 开始。
2. **状态流转**：提议 → 接受；若废弃或被替代，需在**文件顶部加横幅**（`> **状态**：**已替代（Superseded by ADR-00XX）** — 一句话说明新决策`；部分替代同理标注有效/失效部分），front matter 状态行只保留单词取值（`已替代` / `部分已替代`），并在「备注」中写明替代关系，**保留原文件不删除**。
3. **不可变性**：已「接受」的 ADR **禁止回溯修改决策内容**，只能新增 ADR 替代。
4. **行数建议**：80–150 行，避免过度啰嗦；上下文与后果是核心，备选方案要给真实拒绝理由。
5. **代码引用**：用相对路径 markdown 链接（从 `doc/adr/` 出发，如 `../../easyorange-backend/...`），至少 1 处；禁止绝对路径（机器相关、跨端断链）。
6. **语言**：中文写作，避免使用 emoji。
7. **位置**：所有 ADR 存放于 `/home/cartethyia/projects/Java/easy-orange/doc/adr/`。
8. **索引同步**：新增或状态变更（替代/部分替代）后，必须同步更新 [README.md](README.md) 索引（状态、替代链、日期）。
