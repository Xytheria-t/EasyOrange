## ADR 0001 — 订单创建跨模块事务采用 Saga 而非 2PC

- **状态**：已替代（被 [ADR-0007](0007-order-local-tx-over-saga.md) 整体替代）· 日期 2026-07-14
- **当时决策**：订单创建走 **Saga 编排 + 反向补偿**——编排器顺序执行「创建订单 → 同步扣库存 → 创建支付」，失败逆序补偿（恢复库存 → 取消订单）；saga 状态机持久化 + 超时扫描调度；分布式锁按商品排序获取防死锁。
- **当时拒绝**：
  - **2PC / XA（含 Seata AT）**——需要全局事务协调器（新中间件），跨模块 Port/Adapter 边界会被资源管理器穿透，锁等待长；
  - **TCC**——每个参与模块要实现 Try/Confirm/Cancel 三套接口，侵入大、收益不匹配；
  - **纯事件 Choreography**——多步骤流程分散在消费者，链路整体不可见，失败排查成本高；
  - **本地消息表**——适合单发出队场景，不适合有强先后与补偿依赖的编排式流程。
- **为什么被替代**：单库部署下补偿与回滚重复、失败状态随事务回滚丢失，Saga 层整体移除，回归「本地单事务 + 分布式锁 + Outbox」（ADR-0007）。
- **今天仍成立**：
  - **拒绝 2PC / XA / Seata AT / TCC 的结论不变**，且理由覆盖整个 Saga 家族（详见 [ADR-0007](0007-order-local-tx-over-saga.md) 与 [ADR-0010](0010-order-saga-evolution-plan.md)）；
  - **重评估触发**：业务引入资金托管、或 product / payment 拆独立数据源 / 独立部署时，重新评估真 Saga 与事务性 Outbox 补偿。

## ADR 0003 — AI 集成采用 Port/Adapter + 装饰器模式而非直接调用 LLM SDK

- **状态**：已替代（被 [ADR-0008](0008-ai-spring-ai-framework.md) 整体替代）· 日期 2026-07-14
- **当时决策**：六边形 **Port（领域契约，零框架依赖）+ 供应商 Adapter + `@Primary` 装饰器**——业务侧只依赖 Port；底层 Adapter 按 `easyorange.ai.provider` 二选一注册；装饰器叠加 L1 本地缓存 + L2 分布式缓存 + stale 降级；横切关注点（限流拦截器、指标服务）独立成层。
- **当时拒绝**：
  - **业务 Service 直调 LLM SDK**——供应商耦合、缓存 / 限流 / 指标散落各 Service、domain 层被 SDK 污染；
  - **`@Cacheable` + AOP 替代装饰器**——抽象语义是「单级方法返回值缓存」，表达不了「L1 miss 查 L2 → 都 miss 调供应商 → 限流时返回 stale」这类多级 + 降级组合；
  - **只做 Port 不做装饰器**——横切能力会落进底层 Adapter（换供应商即丢缓存）或业务层（污染 domain）；
  - **Spring AI Starter（截至决策日）**——当时尚未稳定，且对多级缓存 / stale 降级 / 按场景分桶的细粒度控制支持不足。
- **为什么被替代**：Spring AI 稳定后，自研 Port / 装饰器 / 缓存适配器 / 指标服务成为与框架重复的手写代码——按 STP（标准 API 优先）原则全部删除，直接注入框架 bean（ADR-0008）。
- **今天仍成立**：供应商切换仍是**改配置**（`AiModelConfig` 的 baseUrl / apiKey / model）；**横切治理（限流 / 预算 / 调用日志）保留在业务层**，只是入口从自研装饰器换成框架 bean + 业务切面；「不为框架已有的能力自研」成为项目的 STP 判据。

## ADR 0004 — AI 调用隔离用 Resilience4j Bulkhead，预算治理用注解 + AOP

- **状态**：部分已替代（Bulkhead 已删；`@TokenBudget` 现役）· 日期 2026-07-26
- **当时决策**：
  - **并发隔离**：Resilience4j `BulkheadRegistry` 三个具名隔离仓（LLM / Vision / 重查询分开），`maxWait` 短超时后抛满仓异常、由调用方转 stale 降级；
  - **预算治理**：`@TokenBudget(scenario, maxTokensPerCall, dailyTokenLimit)` 注解 + AOP 切面——调用前校验日累计预算、调用后记账；`application.yaml` 可按场景覆盖注解默认值。
- **当时拒绝**：**Sentinel**（功能更全但要独立控制台 + 规则存储，对项目规模过重）· **Hystrix**（已停维护）· **Tomcat 线程池隔离**（粒度太粗，分不开同一请求内的 LLM 与 DB 占用）· **拦截器替代 AOP**（拦不到 service 层、拿不到方法级场景语义）· **`@RateLimiter` 替代预算**（语义是 QPS 不是 token）· **tiktoken 类计数器**（国产模型 tokenizer 不准，YAGNI）。
- **今天仍成立 / 已被取代**：
  - **`@TokenBudget` 仍现役**，且职责二分不变——**注解是编译期契约、配置是运行期旋钮**；记账口径已从「按单次上限预估」升级为**按供应商回报的真实用量**（不回报才退化估算，见[技术债务清单](../技术债务清单.md) TD-014）；
  - **Bulkhead 与 Resilience4j 整体已删**（2026-08-13）：重试与并发隔离由框架客户端的连接池承担；缺口是**无跨供应商容灾**（见 TD-016），而不是「缺隔离」。
