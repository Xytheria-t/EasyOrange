### 1.5 安全与可观测

| 指标 | 实现 |
|---|---|
| 认证 | Spring Security OAuth2 Resource Server + RSA JWT Access + Opaque Refresh（Redis、HttpOnly Cookie） |

```bash
k6 run --vus 50 --duration 30s load-tests/product-list.js
# 搜索分项对比（ES 模式与 DB LIKE 模式各跑一轮；k6 不可用时的等价脚本见 load-tests/）
python3 load-tests/mixed-bench.py 50 30
python3 load-tests/search-bench.py 20 30 iPhone
```

**实测数据**（2026-08-15，WSL2 dev 栈，112 个商品 / 105 个在线，`RATE_LIMIT_FILTER_ENABLED=false`）：

| 场景 | 检索模式 | QPS | p50 | p95 | p99 | 失败率 |
|---|---|---|---|---|---|---|
| 混合只读流量（50 并发 30s） | DB LIKE 回退 | **1,025** | 28.7ms | 45.2ms | **52.6ms** | 0% |
| 混合只读流量（50 并发 30s） | ES（IK 分词） | **1,003** | 29.5ms | 45.7ms | **52.9ms** | 0% |
| 搜索专用（20 并发 30s，keyword=iPhone） | DB LIKE 回退 | **1,043** | 14.4ms | 19.6ms | **23.9ms** | 0% |
| 搜索专用（20 并发 30s，keyword=iPhone） | ES（IK 分词） | **959** | 15.2ms | 22.1ms | **28.0ms** | 0% |

**结论**：API p99 目标 < 500ms 达成（实测 53ms 级，留 ~10 倍余量）；112 行小数据集下 DB LIKE 回退与 ES 延迟相当（搜索 p99 24ms vs 28ms），ES 的优势需大数据量（ES 承担 IK 中文分词 + 语义检索，检索效果维度占优，见 §1.3 语义缓存/kNN 链路）。两种模式均 0% 失败率。

## 三、已知限制

### 3.1 WSL2 环境限制

| 限制 | 影响 | 项目应对 |
|---|---|---|
| Mockito inline mock maker 在 WSL2 下 ByteBuddy attach 失败 | 配置 `mock-maker-subclass` 后已跑通（测试全绿） | 原生 Linux / CI 无需该配置 |
| Docker 兼容性 | Testcontainers 集成测试无法跑 | 全量改为单元测试 + Mockito mock |
| Lombok JDK 25 弃用警告 | 启动打印 unsafe 警告 | 已配 `--sun-misc-unsafe-memory-access=allow` |

### 3.2 ES 是可选依赖

Elasticsearch 标记为可选，启动应用不强依赖 ES（`@ConditionalOnProperty`）。这降低部署门槛但意味着"ES 搜索"指标需在装好 ES 的环境单独采集。
