### 1.5 安全与可观测

| 指标 | 实现 |
|---|---|
| 认证 | Spring Security OAuth2 Resource Server + RSA JWT Access + Opaque Refresh（Redis、HttpOnly Cookie） |
| 限流 | `RateLimitFilter` — GET 走本地（200/60s/IP），写走 Redisson 分布式令牌桶（30/60s/IP），fail-open |
| 防重 | `RateLimitFilter` 短时间防连点（3s 间隔 + 请求体 hash） |
| 幂等 | `IdempotencyKeyFilter`（配置驱动，Idempotency-Key + 24h 响应缓存，非 2xx 不缓存） |
| 审计日志 | Spring Modulith **Outbox 模式** — `AuditLogAspect` 发布 `AuditLogEvent` → `AuditLogEventConsumer` 异步入库（崩溃时事件留在 `EVENT_PUBLICATION` 表，重启自动重发） |
| DLQ 三级重试 | `DlqRetryScheduler` 每 5 分钟扫描 DLQ → 重试次数 < 3 重投主队列 → 超过 3 次转储 `eo.dlq.terminal` 等待人工介入（DLQ 层固定轮询间隔，指数退避由主队列 RetryTemplate 承担） |
| L1 缓存广播 | `MultiLevelCache` evict 时 Redis Pub/Sub 广播 → `CacheInvalidationListener` 订阅清除本地 Caffeine（多节点 L1 一致性） |
| CircuitBreaker | Resilience4j — `aiLlm` / `aiVision` / `dbQuery` 三类下游隔离 + Bulkhead 并发限制 |
| 下单链路一致性 | **拒绝 Saga**（[ADR-0007](adr/0007-order-saga-single-tx-observability.md)）：`OrderCreationService.createOrder()` 单一本地 `@Transactional`（订单/库存/支付/Outbox 原子提交）+ Redisson 分布式锁（`DistributedLockManager`，key=`eo:order:lock:product:{productId}`，按 productId 排序防死锁，10s 超时）；任一步失败整体回滚、抛 `OrderCreationException`，无补偿路径 |
| OpenAPI 3 | SpringDoc — `/v3/api-docs` + `/swagger-ui.html`，JWT securityScheme，Controller `@Tag` 分组 |
| XSS | CSP 头 (`default-src 'none'`) |
| 结构化日志 | Spring Boot 4 `StructuredLogEncoder`（logstash JSON 格式） |
| 健康检查 | `/actuator/health` + `/actuator/prometheus` |
| 指标采集 | Micrometer + Prometheus + Spring AI Observation + EventMetrics（事件接收/DLQ/时延） |
| **traceId 全链路传递** | Brave TracingFilter 提取 HTTP 头 → MDC → `MdcTaskDecorator` 传 @Async → `EventMetadataMessagePostProcessor` 注入 RabbitMQ message header → 消费者 decode 回 MDC → 日志 + metrics 统一关联 |

## 二、待实测指标（在原生 Linux/Mac 环境跑）

> 以下指标需要启动应用 + 压测工具才能拿到。JaCoCo 覆盖率报告已可在 WSL2 生成（`mock-maker-subclass` 模式 + `@{argLine}` 注入 agent），下方已填入实测数据；性能/缓存指标仍需启动应用采集。

### 2.1 测试覆盖率（JaCoCo）+ 变异测试（PIT）

```bash
# JaCoCo 覆盖率报告（各模块 target/site/jacoco/index.html）
./mvnw test jacoco:report

# PIT 变异测试（仅 domain 层，HTML 报告 target/pit-reports/index.html）
./mvnw -Ppit test-compile pitest:mutationCoverage
```

**实测数据**（2026-07-26 WSL2，v2 — Domain 工程质量提升后）：

| 范围 | 行覆盖率 | 分支覆盖率 | 说明 |
|---|---|---|---|
| domain 层（聚合根/领域服务/值对象） | **84.1%** ✅ 超越 80% 门禁 | **71.5%** ✅ 超越 60% 门禁 | 补 Product 聚合根状态转换 + 值对象 + 枚举 + OrderAction 动作驱动状态机 + OfflineMessage |
| 全模块聚合（含 adapter/config/DTO） | 45.1% | 36.7% | adapter 靠 ArchUnit 守卫 + 类型系统，未追求全量行覆盖 |
| product 模块 domain（PIT 实测） | 92% | — | **mutation 70% / test strength 79%** |
| order 模块 domain（PIT 实测） | 81% | — | mutation 70% / test strength 89% |

> **测试策略说明**：单元测试聚焦 domain 层业务逻辑（状态机/不变量/校验），adapter/config 层靠 ArchUnit 架构守卫 + Spring 类型系统保证，不追求全量行覆盖（避免为样板代码写无价值测试）。PIT 变异测试作为"金标准"补充——行覆盖率只测"代码被执行过"，PIT 注入变异验证"测试能否发现缺陷"。JaCoCo 门禁（行≥80%/分支≥60%）在 `-Pci` profile，CI 用 `./mvnw -Pci verify` 启用；OWASP 依赖扫描拆到 `-Powasp` profile（CI 非阻断 security job，NVD 境外首次扫描 ~39 分钟不阻塞主门禁）；本地 `./mvnw test jacoco:report` 照常收集覆盖率并出报告，但默认不阻断（`-Djacoco.haltOnFailure=true` 可强制阻断）。domain 层行覆盖 84.1% 已超越门禁，分支覆盖 71.5% 持续优化中。

## 三、已知限制

### 3.1 WSL2 环境限制

| 限制 | 影响 | 项目应对 |
|---|---|---|
| Mockito inline mock maker 在 WSL2 下 ByteBuddy attach 失败 | 配置 `mock-maker-subclass` 后已跑通（测试全绿） | 原生 Linux / CI 无需该配置 |
| Docker 兼容性 | Testcontainers 集成测试无法跑 | 全量改为单元测试 + Mockito mock |
| Lombok JDK 25 弃用警告 | 启动打印 unsafe 警告 | 已配 `--sun-misc-unsafe-memory-access=allow` |

### 3.2 ES 是可选依赖

Elasticsearch 标记为可选，启动应用不强依赖 ES（`@ConditionalOnProperty`）。这降低部署门槛但意味着"ES 搜索"指标需在装好 ES 的环境单独采集。
