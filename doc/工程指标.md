> **重新测量时的坑**：surefire XML 有两个独立偏差，故**一律以 maven 控制台的 `Tests run:` 汇总为准**。
> 一是**残留高估**：`target/surefire-reports/` 跨次运行不自动清理，直接汇总 `TEST-*.xml` 会把已删测试类的历史报告算进来（2026-09-17 当日早先一次运行实测：全量 XML 汇总 1,954，而 maven 当时自报 1,788）。
> 二是**属性低估**：干净运行下 `testsuite` 的 `tests="N"` 属性也小于实际执行数（1,811 那轮复核：属性汇总 1,787 vs 控制台 1,811，缺口 24 落在 user/product 两个 `@Nested` 最多的模块）；改数 `<testcase>` 元素则与控制台**完全一致**。要用 XML 口径请先 `./mvnw clean test` 并数 `<testcase>`，不要数 `tests=`。
> 另：`.mvn/maven.config` 开了 `-T1C` 并行构建，模块的 "Building" 行与测试汇总行会交错，按日志顺序去对应「哪条汇总是哪个模块」会错配——要逐模块数字用 `./mvnw -T1 test`。

| 架构守卫测试 | ArchUnit `ArchitectureRulesTest`（**12 条规则**） | `easyorange-application/src/test/java/.../architecture/` |
| 变异测试（PIT 1.25.9，全模块 domain 层实测） | **全量 765 变异 / 约 3 分钟跑完**（CI nightly 完全跑得起）：order mutation **76%** / test strength **78%** / line **93%**（75 变异）；product mutation **64%** / test strength **74%** / line **92%**（281 变异）；payment 84%/92%、message 76%/91%、user 69%/80% | `./mvnw -Ppit test-compile pitest:mutationCoverage`，HTML 报告 `target/pit-reports/index.html` |

> **三个口径说明**：源码里 `@Test`/`@ParameterizedTest`/`@RepeatedTest` 注解物理出现 **1,763** 次；surefire 控制台报的实际用例数 **1,821**（参数化按参数个数展开，故比注解数多）；surefire XML 的 `tests=` 汇总**不可直接采信**（见上条）。引用时统一用**控制台口径 1,821**。
