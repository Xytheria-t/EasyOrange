### 1.5 安全与可观测

| 指标 | 实现 |
|---|---|
| 认证 | Spring Security OAuth2 Resource Server + RSA JWT Access + Opaque Refresh（Redis、HttpOnly Cookie） |
| 限流 | `RateLimitFilter` — GET 走本地（200/60s/IP），写走 Redisson 分布式令牌桶（30/60s/IP），fail-open |
| 防重 | `RateLimitFilter` 短时间防连点（3s 间隔 + 请求体 hash） |
| 幂等 | `IdempotencyKeyFilter`（配置驱动，Idempotency-Key + 24h 响应缓存，非 2xx 不缓存） |
| 审计日志 | Spring Modulith **Outbox 模式** — `AuditLogAspect` 发布 `AuditLogEvent` → `AuditLogEventConsumer` 异步入库（崩溃时事件留在 `EVENT_PUBLICATION` 表，重启自动重发） |
| DLQ 三级重试 | `DlqRetryScheduler` 每 5 分钟扫描 DLQ → 重试次数 < 3 重投主队列 → 超过 3 次转储 `eo.dlq.terminal` 等待人工介入（DLQ 层固定轮询间隔，指数退避由主队列 RetryTemplate 承担） |
| 缓存 | Spring Cache 注解式 + Redis 单层（`RedisCacheConfig`）：统一 TTL（`easyorange.cache.default-ttl` 默认 30m）+ 写路径显式 `@CacheEvict` + `CacheErrorHandler` fail-open（Redis 故障读直查 DB、写放弃缓存）。手写多级缓存（L1 Caffeine + Pub/Sub 广播）已移除（2026-08-13） |
| CircuitBreaker | Resilience4j 已移除（2026-08-13，无消费者）；缓存故障降级由 `RedisCacheConfig` `CacheErrorHandler` fail-open 承担；AI 重试/并发隔离由 openai-java 客户端内置（[ADR-0008](adr/0008-ai-spring-ai-framework.md)） |
| 下单链路一致性 | **拒绝 Saga**（[ADR-0007](adr/0007-order-local-tx-over-saga.md)）：`OrderCommandHandler.handle(CreateOrderCommand)` 单一本地 `@Transactional`（订单/库存/支付/Outbox 原子提交）+ Redisson 分布式锁（`DistributedRedissonLockAdapter`，key=`eo:order:lock:product:{productId}`，按 productId 排序防死锁，10s 超时）；任一步失败整体回滚、抛 `OrderCreationException`，无补偿路径 |
| OpenAPI 3 | SpringDoc — `/v3/api-docs` + `/swagger-ui.html`，JWT securityScheme，Controller `@Tag` 分组 |
| XSS | CSP 头 (`default-src 'none'`) |
| 结构化日志 | Spring Boot 4 `StructuredLogEncoder`（logstash JSON 格式） |
| 健康检查 | `/actuator/health` + `/actuator/prometheus` |
| 指标采集 | Micrometer + Prometheus + Spring AI Observation + EventMetrics（事件接收/DLQ/时延） |

### 3.2 ES 是可选依赖

Elasticsearch 标记为可选，启动应用不强依赖 ES（`@ConditionalOnProperty`）。这降低部署门槛但意味着"ES 搜索"指标需在装好 ES 的环境单独采集。
