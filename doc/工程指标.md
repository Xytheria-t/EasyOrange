### 3.1 WSL2 环境限制

| 限制 | 影响 | 项目应对 |
|---|---|---|
| Mockito inline mock maker 在 WSL2 下 ByteBuddy attach 失败 | 配置 `mock-maker-subclass` 后已跑通（1,369 全绿） | 原生 Linux / CI 无需该配置 |

### 3.2 ES 是可选依赖

Elasticsearch 标记为可选，启动应用不强依赖 ES（`@ConditionalOnProperty`）。这降低部署门槛但意味着"ES 搜索"指标需在装好 ES 的环境单独采集。

### 1 分钟版本（面试自我介绍）

> 我做了一个叫 EasyOrange 的项目，定位是 **LLM × DDD 工程化实战**——在 DDD 六边形架构里集成 LLM，让 AI 链路可换供应商、可降级、可观测。
>
> 核心矛盾：DDD 铁律要求 domain 层零框架依赖，但 LLM 调用昂贵且不稳定必须有多级缓存 + 限流降级 + 可观测。我的解法是 Port/Adapter + 装饰器——`LlmPort` 接口在 domain 层，`@Primary` 装饰器 `CachingLlmAdapter` 在 adapter 层包裹 DeepSeek 实现 L1 Caffeine + L2 Redis 多级缓存；`AiRateLimitInterceptor` 令牌桶按端点限流，超限返回 stale 缓存而不是 429；`AiMetricsService` 把缓存命中率 / LLM p99 / 限流计数暴露到 Prometheus。**6 个 AI 决策点全部走这套链路**，加上 `@TokenBudget` 日预算治理 + Prompt YAML 版本化 + Resilience4j Bulkhead 并发隔离形成完整 7 件套。
>
> 架构上 **11 模块** DDD 六边形 + **31 个 Port 接口**全编译期隔离 + ArchUnit 守卫；事件驱动 RabbitMQ + **12 消费者** + DLQ 三级重试（指数退避 + terminal 队列转储毒消息）；审计日志走 Spring Modulith Outbox 保证事务一致性；分布式事务 Saga 编排 + 反向补偿，7 状态机（含 TIMEOUT / MANUAL_INTERVENTION）持久化到 `eo_saga` 表。**5 条 ADR 记录每个"为什么这样选 + 拒绝了什么"**（Saga over 2PC / CQRS scope / AI Port-Adapter / AI Bulkhead+TokenBudget / 模块解耦）。测试守卫 **2,289 用例**（后端 1,369 + 前端 920），JaCoCo 行/分支覆盖率门禁 + PIT 变异测试评估测试对缺陷的真实检测能力（order 模块 mutation 70% / test strength 89%）。

### 被问"为什么不用 2PC"时

> 见 [ADR 0001](./adr/0001-use-saga-over-2pc.md)。三个原因：①平台不经手资金，无 double-spend 风险；②已有 RabbitMQ 基础设施，Saga 编排天然复用；③模块边界已用 Port 隔离，2PC 的强一致收益不抵工程成本。**拒绝了 Seata / XA**。Saga 状态机持久化到 `eo_saga` 表，故障后可 `retryFailedSaga(sagaId)` 重试。

### 被问"AI 怎么工程化的"时

> 见 [ADR 0003](./adr/0003-ai-port-adapter-with-decorator.md) + [ADR 0004](./adr/0004-ai-bulkhead-and-token-budget.md)。核心矛盾是 domain 层零框架依赖 vs LLM 不稳定。解法是 **Port/Adapter + 装饰器 + 7 件套**：
> - `LlmPort` / `VisionPort` 接口在 domain 层 — 供应商可换
> - `@Primary` 装饰器 `CachingLlmAdapter` 包裹 `DeepSeekLlmAdapter`，实现 L1 Caffeine + L2 Redis 多级缓存
> - `AiRateLimitInterceptor` Redisson 令牌桶按端点独立限流（5-30 次/分），超限时返回 stale 缓存而不是 429
> - `AiMetricsService` 暴露缓存命中率 / LLM 延迟 / 限流计数到 Prometheus
> - Prompt 版本化（6 个 YAML 模板 + `{var}` 渲染）
> - `@TokenBudget` AOP 切面 — 6 个 AI 场景全部接入日预算控制
> - Resilience4j Bulkhead 隔离 AI/DB 调用（aiLlm 并发 8 / aiVision 并发 4 / dbHeavy 并发 16）
>
> **关键词：可换供应商、可降级、可观测——不是调通 API，是工程化**。

### 被问"事件驱动可靠性怎么保证"时

> 三层保障：① **Spring Modulith Outbox** — `AuditLogAspect` 发布 `AuditLogEvent` 与业务事务同原子写入 `EVENT_PUBLICATION` 表，崩溃后重启自动重发，不丢审计日志。② **DLQ 三级重试** — 消费失败消息路由到 DLQ，`DlqRetryScheduler` 每 5 分钟扫描并指数退避重投主队列（1min/5min/15min），超过 max-retries=3 的毒消息转储 `eo.dlq.terminal` 等待人工介入。③ **Saga 7 状态机** — `SagaTimeoutScheduler` 每分钟扫描活跃 saga，超过 30 分钟未更新标记 TIMEOUT，重试次数耗尽标记 MANUAL_INTERVENTION，防止 saga 永久挂起。
