启动应用后访问：

```bash

curl http://localhost:8080/actuator/prometheus | grep easyorange_ai_

# 关键指标
# - easyorange_ai_cache_hits_total
# - easyorange_ai_cache_misses_total
# - easyorange_ai_llm_latency_seconds{quantile="0.99"}
```

## 三、已知限制

### 3.1 WSL2 环境限制

| 限制 | 影响 | 项目应对 |
|---|---|---|
| Mockito MockMaker attach 受沙箱限制 | 单元测试无法跑通 | 文档化"应在 Linux 原生或 CI 跑测试" |
| Docker 兼容性 | Testcontainers 集成测试无法跑 | 全量改为单元测试 + Mockito mock |
| Lombok JDK 25 弃用警告 | 启动打印 unsafe 警告 | 已配 `--sun-misc-unsafe-memory-access=allow` |

### 3.2 ES 是可选依赖

Elasticsearch 标记为可选，启动应用不强依赖 ES（`@ConditionalOnProperty`）。这降低部署门槛但意味着"ES 搜索"指标需在装好 ES 的环境单独采集。

## 四、面试话术示例

### 30 秒钩子（简历顶部）

> **EasyOrange** — 把 LLM 工程化集成进企业级 Java 应用的全栈样板。**11 模块 DDD 六边形 · 28 个 Port 接口全编译期隔离 · 9 RabbitMQ 消费者 + DLQ · 6 AI 决策点 Port/Adapter + L1/L2 多级缓存 + 令牌桶限流 + stale 降级 + AiMetrics 可观测 · 2,214 测试守卫 · Java 25 + Spring Boot 4 + React 19**。

### 1 分钟版本（面试自我介绍）

> 我做了一个叫 EasyOrange 的全栈项目，定位是 LLM 时代企业级 Java 应用的工程化样板。业务载体是简化的 C2C 资产流转——刻意简化是因为项目核心是工程深度，不是商业。
>
> 工程亮点：**11 个 Maven 模块**用 DDD 六边形 + 端口-适配器全编译期隔离，**28 个 Port 接口**让模块边界可被 ArchUnit 守卫；事件驱动用 RabbitMQ Topic Exchange + **9 个消费者** + DLQ + 指数退避；分布式事务用 Saga 编排 + 反向补偿，状态机持久化到 `eo_saga` 表支持故障重试。
>
> AI 工程化是核心叙事——**6 个 AI 决策点全部走 Port/Adapter + L1/L2 多级缓存 + 令牌桶限流 + stale 降级 + AiMetrics 可观测**，让 AI 从"demo 调用"走到"生产级工程"。测试守卫 **2,214 用例**（后端 1,269 + 前端 945）。

### 被问"为什么不用 2PC"时

> 见 [ADR 0001](./adr/0001-use-saga-over-2pc.md)。三个原因：①平台不经手资金，无 double-spend 风险；②已有 RabbitMQ 基础设施，Saga 编排天然复用；③模块边界已用 Port 隔离，2PC 的强一致收益不抵工程成本。Saga 状态机持久化到 `eo_saga` 表，故障后可 `retryFailedSaga(sagaId)` 重试。

### 被问"AI 怎么工程化的"时

> 见 [ADR 0003](./adr/0003-ai-port-adapter-with-decorator.md)。核心是 **Port/Adapter + 装饰器四件套**：
> - `LlmPort` / `VisionPort` 接口抽象，供应商可换
> - `@Primary` 装饰器 `CachingLlmAdapter` 包裹 `DeepSeekLlmAdapter`，实现 L1 Caffeine + L2 Redis 多级缓存
> - `AiRateLimitInterceptor` 令牌桶按端点独立限流（5-30 次/分），超限时返回 stale 缓存
> - `AiMetricsService` 暴露缓存命中率 / LLM 延迟 / 限流计数到 Prometheus
