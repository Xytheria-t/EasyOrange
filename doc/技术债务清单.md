## 二、债务清单

### 2.1 测试与 CI

#### TD-001 · 集成测试真实基础设施覆盖（已还 · 2026-08-07）

**现状**：集成测试已从「Testcontainers 依赖 → 静默跳过」演进为 **Spring Boot docker-compose 复用 dev 栈**：`AbstractIntegrationTest` 去掉 `@Testcontainers` / `@ServiceConnection` / `@DynamicPropertySource`，改由 `spring-boot-docker-compose`（`spring.docker.compose.file` 指向仓库根 `compose.yaml`，`lifecycle-management: start-only`）保证基础设施运行，连接走 `application-it.yaml` 显式 localhost 直连（凭据与 compose.yaml 服务一致）；`*IT` 经 failsafe 绑定 `mvn verify`（`mvn test` 保持快速单测）。
**归还说明**：
- **为何弃用 Testcontainers**：其 ryuk sidecar 镜像在无代理 Docker 下拉取失败，`@Testcontainers(disabledWithoutDocker=true)` 会**静默跳过**，掩盖真实装配错误（`DatabaseConnectivityIT` 此前从未真正运行）。
- **迁移时修复了两处被跳过掩盖的装配缺陷**：`PaymentGatewayAdapter`、`MockSmsSenderAdapter` 原为 `@Profile("dev")` 门控，IT profile(`it`) 下对应 Port 无 bean，已扩展 `@Profile({"dev","it"})`。
- **复用 dev 库时关闭 Flyway 迁移校验**（`validate-on-migrate: false`）：dev 库迁移历史与当前脚本可能 diverged（repeatable seed 曾从仓库移除），迁移校验归干净库/CI 承担。
**遗留限制**：IT 复用开发者持久 dev 库（非一次性数据库），跨运行存在数据残留；完整隔离式测试库可作为后续增强。

**关联**：[AGENTS.md 测试策略段](../easyorange-backend/AGENTS.md)、[doc/工程指标.md §3.1](./工程指标.md)

---

#### TD-002 · JaCoCo 覆盖率门禁未在本地强制（接受）

**现状**：JaCoCo 配置只在 `prepare-package` 阶段生成报告，门禁移到 CI 层。
**原因**：本地开发优先编译速度，CI 兜底覆盖率。
**代价**：开发者本地提交前看不到覆盖率红线，可能引入未覆盖代码。
**缓解措施**：[doc/工程指标.md §2.1](./工程指标.md) 提供本地跑 JaCoCo 的命令。

### 2.2 基础设施依赖

#### TD-003 · Elasticsearch 标记为可选依赖（接受）

**现状**：`@ConditionalOnProperty(name = "easyorange.search.es.enabled", matchIfMissing = true)` 控制 ES 启用，无 ES 也能跑应用。
**原因**：降低部署门槛，开发者可以不装 ES 跑起来。
**代价**：
- `SemanticSearchService`、`ProductSearchQueryPort` 等 ES 路径在无 ES 环境无法验证
- 单元测试只覆盖 mock 路径，ES 实际查询 DSL 错误只能在生产暴露

**触发重评估条件**：进入需要全文搜索的生产部署时，必须改为强依赖 + 健康检查。

---

#### TD-004 · Redis 单点 + 未做哨兵/集群（待评估）

**现状**：单 Redis 实例，未配置 Sentinel 或 Cluster。
**原因**：开发期 + demo 期单点足够。
**代价**：Redis 故障时 `RateLimitFilter` fail-open（允许请求通过），`AiRateLimitInterceptor` 令牌桶同样 fail-open（直接走 LLM）——可用性下降但不会阻塞。
**触发重评估条件**：进入生产环境时升级为 Sentinel 或 Redis Cluster。

### 2.3 AI 工程化

#### TD-005 · AI 调用未做 token 成本治理（已还 · 2026-07-22）

**现状**：**已实现** `@TokenBudget` 注解 + `TokenBudgetAspect` 切面 + `TokenBudgetStore`（当前 `InMemoryTokenBudgetStore`），按场景/用户做日预算 token 控制。AI 工程化 8 件套之 Token 预算治理已落地。
**归还说明**：原触发条件"补 `@TokenBudget` 注解 + 切面"已完成。存储层当前为 InMemory（单实例），生产环境多实例部署时需替换为 Redis-backed `TokenBudgetStore` 实现（属生产硬化，非核心债）。
**关联设计**：见 [doc/adr/0003-ai-port-adapter-decorator.md](./adr/0003-ai-port-adapter-decorator.md)

---

#### TD-006 · Prompt 硬编码在 service 类中（已还 · 2026-07-22）

**现状**：**已实现** `PromptRegistry` + `YamlPromptRegistry` + `PromptTemplate`，Prompt 模板存放在 `src/main/resources/prompts/*.yml`（如 `product_tag_generation.yml`），模板即 system prompt，业务变量由服务内联 `String.format` 填充（原 `PromptRenderer` `{var}` 渲染已于 2026-08-12 收敛移除）。AI 工程化 8 件套之 Prompt 版本化已落地。
**归还说明**：原触发条件"引入 `PromptRegistry`（YAML/DB）+ `PromptRenderer`"已完成。Prompt 修改无需重新编译部署。

---

#### TD-007 · AI 失败降级策略单一（接受）

**现状**：AI 调用失败时仅 fail-open（返回 null 或 stale 缓存）。
**原因**：业务侧已设计为"AI 增强非必需"——AI 失败不影响主流程。
**代价**：用户感知不到 AI 降级（无降级提示）。
**缓解措施**：Spring AI 2.0 内置 Observation 暴露 AI 调用成功率/延迟指标，可在监控面板观察降级频率。

### 2.4 安全与运维

#### TD-008 · JWT 密钥从配置文件读取（接受）

**现状**：JWT 签名密钥从 `application.yml` 读取，未接 Vault / AWS Secrets Manager。
**原因**：项目定位是架构演示，未接生产级密钥管理。
**代价**：密钥轮换需重启应用；多实例部署时密钥需手动同步。
**缓解措施**：`application.yml` 已区分 dev / prod profile，prod profile 强制要求环境变量注入。
**触发重评估条件**：进入生产部署时接入 Vault 或 AWS Secrets Manager。

---

#### TD-009 · 文件上传未做病毒扫描（待评估）

**现状**：用户头像 / 商品图片上传只校验 MIME 类型和大小，未做病毒扫描。
**原因**：未引入 ClamAV 等扫描服务。
**代价**：理论上可上传带毒图片（虽不会在服务端执行）。
**触发重评估条件**：进入生产环境时接入 ClamAV 或云厂商内容安全服务。

### 2.5 工程化

#### TD-010 · Lombok 在 JDK 25 下产生 unsafe 警告（接受）

**现状**：启动时打印 `WARNING: A terminally deprecated method in sun.misc.Unsafe is called`。
**原因**：Lombok 1.18.x 仍使用 `sun.misc.Unsafe` API，在 JDK 25 下被标记为 terminally deprecated。
**代价**：日志噪音，未来 JDK 版本可能彻底移除导致 Lombok 失效。
**缓解措施**：JVM 启动参数已配 `--sun-misc-unsafe-memory-access=allow`。
**触发重评估条件**：Lombok 升级到完全支持 JDK 25 的版本后移除该 JVM 参数。

---

#### TD-011 · 模块循环依赖通过 `<optional>` 隔离但未用 ArchUnit 强制（接受）

**现状**：跨模块 Port/Adapter 通过 Maven `<optional>true</optional>` 实现编译期隔离，ArchUnit 守卫已覆盖包依赖方向，**但未显式校验 `<optional>` 标记**。
**原因**：ArchUnit 不直接读 Maven pom.xml 元数据。
**代价**：开发者可能忘记标记 `<optional>`，导致下游模块意外传递依赖。
**缓解措施**：CI 层用 `mvn dependency:tree` + grep 校验关键依赖的 optional 标记。

---

#### TD-012 · Flyway 只有一个 V1 初始化脚本（接受）

**现状**：所有表结构在一个 `V1__init_schema.sql` 中，无增量迁移脚本。
**原因**：项目未经历多次结构演进。
**代价**：表结构演进时需手工写 V2，无演进历史可追溯。
**决策注记（2026-08-15）**：8-07~8-14 期间曾拆出 V2~V9 增量脚本，开发阶段收口时合并回单文件 V1（32 张表全量，`refactor(db)` 提交），演进期按触发条件再拆增量。
**触发重评估条件**：表结构首次变更时开始用 V2、V3 增量脚本。

## 四、维护与更新

| 触发条件 | 操作 |
|---|---|
| 新增技术债 | 按 §一 格式添加，编号递增 TD-XXX |
| 债务已还 | 状态改为 "已还" + 添加归还日期，不删除记录 |
| 触发重评估条件命中 | 状态从"接受/待评估"升级为"必须还"，进入下个迭代 |
| 每次发布前 | 复盘本清单，确认无"必须还"债务遗留 |

> **不主动还债的判断标准**：当还债的工程成本 > 债务当前造成的实际损失时，选择不还并文档化。这是工程判断，不是技术懈怠。
