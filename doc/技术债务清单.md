### 2.1 测试与 CI

#### TD-001 · 集成测试真实基础设施覆盖（已还 · 2026-08-07）

**现状**：集成测试已从「Testcontainers 依赖 → 静默跳过」演进为 **Spring Boot docker-compose 复用 dev 栈**：`AbstractIntegrationTest` 去掉 `@Testcontainers` / `@ServiceConnection` / `@DynamicPropertySource`，改由 `spring-boot-docker-compose`（`spring.docker.compose.file` 指向仓库根 `compose.yaml`，`lifecycle-management: start-only`）保证基础设施运行，连接走 `application-it.yaml` 显式 localhost 直连（凭据与 compose.yaml 服务一致）；`*IT` 经 failsafe 绑定 `mvn verify`（`mvn test` 保持快速单测）。运行位置：本地/开发机 `mvn verify` 真实连 MySQL/Redis/RabbitMQ；PR 门禁 `backend-ci.yml` 以 `-DskipITs=true` 跳过（runner 无 dev 栈），nightly `ai-eval.yml` 在 runner 上跑 `GoldenSetRegressionIT`。
**归还说明**：
- **为何弃用 Testcontainers**：其 ryuk sidecar 镜像在无代理 Docker 下拉取失败，`@Testcontainers(disabledWithoutDocker=true)` 会**静默跳过**，掩盖真实装配错误（`DatabaseConnectivityIT` 此前从未真正运行）。
- **迁移时修复了两处被跳过掩盖的装配缺陷**：`PaymentGatewayAdapter`、`MockSmsSenderAdapter` 原为 `@Profile("dev")` 门控，IT profile(`it`) 下对应 Port 无 bean，已扩展 `@Profile({"dev","it"})`。
- **复用 dev 库时关闭 Flyway 迁移校验**（`validate-on-migrate: false`）：dev 库迁移历史与当前脚本可能 diverged（repeatable seed 曾从仓库移除），迁移校验归干净库/CI 承担。
**遗留限制**：IT 复用开发者持久 dev 库（非一次性数据库），跨运行存在数据残留；完整隔离式测试库可作为后续增强。

**关联**：[doc/工程指标.md §1.2 测试规模 / §3.1 已知限制](./工程指标.md)、[架构-DDD规范.md 测试分层策略](./架构/架构-DDD规范.md)、[常用命令.md 后端构建与测试](agents/常用命令.md)、[开发规范.md 后端约定](agents/开发规范.md)

#### TD-002 · JaCoCo 覆盖率门禁未在本地强制（接受）

**现状**：JaCoCo 配置只在 `prepare-package` 阶段生成报告，门禁移到 CI 层。
**原因**：本地开发优先编译速度，CI 兜底覆盖率。
**代价**：开发者本地提交前看不到覆盖率红线，可能引入未覆盖代码。
**缓解措施**：[doc/工程指标.md §2.1](./工程指标.md) 提供本地跑 JaCoCo 的命令。

### 2.2 基础设施依赖

#### TD-003 · Elasticsearch 标记为可选依赖（接受）

**现状**：`@ConditionalOnProperty(name = "easyorange.search.elasticsearch.enabled", havingValue = "true")` 控制 ES 装配（默认 `false`，无 ES 也能跑应用）；开关关闭时 `KnowledgeFallbackAdapter` / `ProductSearchIndexAdapter` 接管。
**原因**：降低部署门槛，开发者可以不装 ES 跑起来。
**代价**：
- `SemanticSearchService`、`ProductSearchQueryPort` 等 ES 路径在无 ES 环境无法验证
- 单元测试只覆盖 mock 路径，ES 实际查询 DSL 错误只能在生产暴露
- 检索降级链路召回质量差：无 ES 时 RAG 检索走 MySQL LIKE，实测 hit@5 仅 10%（20 条金标准检索用例），检索类断言在无 ES 环境必然失败

**已有缓解**：
- **CI 覆盖**：weekly `ai-eval.yml` 起 ES（`docker compose --profile search`）并以 `-Deasyorange.search.elasticsearch.enabled=true` 跑 `GoldenSetRegressionIT`，知识库 ES 召回路径每周真实执行一次（实测 hit@5 100% / MRR 0.95）；`ElasticsearchProductSearchIT`（商品检索 DSL）仍需 ES 预启动，不在 CI 路径。
- **生产不再可选**：`application-prod.yaml` 显式 `enabled: true`，并由 `ProdSearchGuard`（`@Profile("prod")`）校验——被环境变量覆盖回 `false` 时启动中止（生产必需依赖的契约与 `ProdSecrets` 一致）；ES 启用但不可达时，`ElasticsearchIndexManager` 的 `@PostConstruct` 建索引失败同样中止启动。
- **降级不再静默**：`KnowledgeFallbackAdapter` 启动打 WARN 说明后果，按调用累计 `easyorange.ai.rag.degraded`；`RagHealthIndicator` 在 `/actuator/health` 报 `UNKNOWN` 并标注「LIKE 兜底 / 实测 hit@5 10%」。

**残留代价**：dev/test 仍是无 ES 也可跑（保「零配置启动」），此时 RAG 召回退化为 LIKE —— 已知且可观测，但不代表召回可用；商品检索 DSL 仍无 CI 覆盖。

**触发重评估条件**：若未来需要支持「无 ES 的生产部署」，必须先把 RAG 召回的替代实现（如进程内向量检索或 VectorStore）落地并纳入门禁，否则不能移除 `ProdSearchGuard`。

#### TD-004 · Redis 单点 + 未做哨兵/集群（待评估）

**现状**：单 Redis 实例，未配置 Sentinel 或 Cluster。
**原因**：开发期 + demo 期单点足够。
**代价**：Redis 故障时 `RateLimitFilter` fail-open（允许请求通过），`AiRateLimitInterceptor` 令牌桶同样 fail-open（直接走 LLM）——可用性下降但不会阻塞。
**触发重评估条件**：进入生产环境时升级为 Sentinel 或 Redis Cluster。

#### TD-007 · AI 失败降级策略单一（接受）

**现状**：AI 调用失败时仅 fail-open（返回 null 或 stale 缓存）。
**原因**：业务侧已设计为"AI 增强非必需"——AI 失败不影响主流程。
**代价**：用户感知不到 AI 降级（无降级提示）。
**缓解措施**：Spring AI 2.0 内置 Observation 暴露 AI 调用成功率/延迟指标，可在监控面板观察降级频率。

### 2.4 安全与运维

#### TD-008 · JWT 密钥从配置文件读取（接受）

**现状**：JWT 签名密钥从 `application.yml` 读取，未接 Vault / AWS Secrets Manager。
**原因**：项目定位是架构演示，未接生产级密钥管理。
**代价**：密钥轮换需重启应用；多实例部署时密钥需手动同步。
**缓解措施**：`application.yml` 已区分 dev / prod profile，prod profile 强制要求环境变量注入。
**触发重评估条件**：进入生产部署时接入 Vault 或 AWS Secrets Manager。

---

#### TD-009 · 文件上传未做病毒扫描（待评估）

**现状**：用户头像 / 商品图片上传只校验 MIME 类型和大小，未做病毒扫描。
**原因**：未引入 ClamAV 等扫描服务。
**代价**：理论上可上传带毒图片（虽不会在服务端执行）。
**触发重评估条件**：进入生产环境时接入 ClamAV 或云厂商内容安全服务。

### 2.5 工程化

#### TD-010 · Lombok 在 JDK 25 下产生 unsafe 警告（接受）

**现状**：启动时打印 `WARNING: A terminally deprecated method in sun.misc.Unsafe is called`。
**原因**：Lombok 1.18.x 仍使用 `sun.misc.Unsafe` API，在 JDK 25 下被标记为 terminally deprecated。
**代价**：日志噪音，未来 JDK 版本可能彻底移除导致 Lombok 失效。
**缓解措施**：JVM 启动参数已配 `--sun-misc-unsafe-memory-access=allow`。
**触发重评估条件**：Lombok 升级到完全支持 JDK 25 的版本后移除该 JVM 参数。

#### TD-011 · 模块循环依赖通过 `<optional>` 隔离但未用 ArchUnit 强制（已还 · 2026-08-16）

**现状**：跨模块 Port/Adapter 通过 Maven `<optional>true</optional>` 实现编译期隔离，ArchUnit 守卫已覆盖包依赖方向，**但未显式校验 `<optional>` 标记**。
**归还说明**：新增 [.github/scripts/check-optional-deps.py](../.github/scripts/check-optional-deps.py) 并接入 [backend-ci.yml](../.github/workflows/backend-ci.yml)——除组合根 `easyorange-application` 外，任意模块依赖其他领域模块（`framework`/`common` 基础模块除外）必须声明 `<optional>true</optional>`，违规即 CI 失败；本地复跑：`python3 .github/scripts/check-optional-deps.py easyorange-backend`。

#### TD-014 · AI 成本治理是静态预估口径（接受）

**现状**：`@TokenBudget` 按注解 / 配置的 `maxTokensPerCall` 静态预估扣减（`TokenBudgetAspect` 调 `recordUsage(scenario, maxPerCall, 0)`，输出恒 0），不是真实 token 计数；预算计数存单 JVM 内存（key = 场景:日期，无 TTL，重启清空）。语义缓存（`SemanticCacheService`）无 hit/miss 计数器，命中率不可从现有代码测得，且命中路径照常调用 embedding、照常扣满一次预估。
**原因**：六个 AI 服务返回业务 DTO 而非 `ChatResponse`，取真实 usage 需改造返回值契约（YAGNI）；`eo_ai_call_log` 也没有 token 列。
**代价**：预算校准依赖人工估算；对外口径只能是「按场景日预算拦截超限调用」，不能讲「真实成本可观测」，也给不出缓存命中率数字。
**触发重评估条件**：需要按用户 / 租户计费或出成本报表时——届时解析 `ChatResponse` 的 usage metadata、`eo_ai_call_log` 补 token 列、`SemanticCacheService` 加命中计数器。

## 四、维护与更新

| 触发条件 | 操作 |
|---|---|
| 新增技术债 | 按 §一 格式添加，编号递增 TD-XXX |
