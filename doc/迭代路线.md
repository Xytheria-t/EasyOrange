> **用途**：本文件是**排期与验收线**的单一落点（旧「Agent 工程化升级」时段表已作废）。依据：2026-09-20 重排共识——目标 = 2027 寒假拿到一段远程 AI 应用实习。
> **数字纪律**：每步先更新 [工程指标.md](工程指标.md)，再回填简历与面试脚本——顺序不能反。
> **结构计数**（模块 / Port / ADR / 消费者 / 表 / 规则 / 模板 / 金标准集）只在 [工程指标 §结构计数](工程指标.md#结构计数) 维护，本文件不复刻。
> **取舍判据**：功能增删改按 [AGENTS.md](../AGENTS.md)「功能取舍判据」（演示 + 面试 ROI）；本文件只管「什么时候做到什么程度」。

## 一、立即动作（本周）

- **英语考试报名**：2026-12-12（周六）四六级笔试；成都大学报名窗口 **2026-09-20 12:00 ~ 09-28 17:00**，报六级需四级 ≥425 分。**窗口只剩 8 天，错过下一次是 2027-06。**
- **旧简历已归档**（2026-09-20）：成品 HTML / PDF 移入 `Documents/求职/简历/_archive/`——里面的测试总数 / 覆盖率 / PIT / QPS 数字来源已被工程指标撤下，投出去会被追问到来源。`_shell/` 保留，它是重建底板。

## 二、目标（按优先级）

1. **2027 寒假拿到一段远程 AI 应用方向实习**——形态是**长期远程**（寒假起步、开学后延续到 2027-06，每周 8-15h），不是 6 周短工：只有 6 周的岗位几乎投不出去，且「实习中」在春招里比「实习过 6 周」有说服力。
2. **落点保底**：寒假产出一个**开源 merged PR**（Java AI 生态：LangChain4j / Spring AI / MCP Java SDK——与主线同栈、读代码成本最低），不受开学不能延续与春节停摆影响，且公开可验证。
3. **尾部目标（真正的大奖）**：2027 春（3-5 月）投「大二升大三暑期实习」，双项目叙事就位。

## 四、三件事与时间预算

## 六、投递与资产口径

**渠道**：BOSS 直聘 + 实习僧（远程标签）为主；牛客 / 即刻 / V2EX 远程板块补充；开源社区里认识的人是内推来源。

**话术骨架**：「大二，远程，寒假每周可投 20h、开学后 15h，能做 6 个月以上」——把「寒假 6 周」说成「长期可延续」，这是岗位池大一个量级的关键。**「开学后能延续」必须先在三、待确认里坐实，不能说没把握的话。**

**匹配策略**：AI 应用 / Agent 方向的中小厂与创业公司为主（一线大厂几乎不做远程）；不限语言投，简历按 JD 微调。

**简历**：目标版（= 对着学的验收清单）→ 投递版（投递前做减法）→ Windows 简历壳重渲染（`_shell/print-preview-qa.py`；模板 CSS 在 `~/.agents/skills/asu-skills/assets/frame/asu/base.css`，渲染时需与 `icons/`、`logos/` 同目录）。重建时数字一律取工程指标实测值，取不到就不写。

**Agent 知识学习清单**（出关机制见 [00-怎么说.md §〇](interview/00-怎么说.md)）：ReAct 论文口径 +「工具循环 vs Function Calling」差异应答 · MCP 协议（JSON-RPC / 传输 / tool schema）· LangGraph 与自研循环的对比应答 · RAG 评估指标与 RAGAS 口径 · 多智能体范式（第二项目预习）。

**工程剩余事项**（与能讲化同源，不单列排期）：

- **数字补测**（口径与复现命令见 [工程指标 §二](工程指标.md)）：**AI 侧跑量指标（循环三口径 / 上下文注入 token / 检索指标 / RAG 有效性对照）依赖真实 key，按 [AGENTS.md](../AGENTS.md) 规则标记后搁置**，不阻塞投递；测试规模 / 覆盖率 / PIT / 压测四类不依赖 key，进 P2-P3。
- **演示素材**：GIF 三条（多步 Agent 找货流式 / Cursor 连 MCP 实时查在售商品 / Langfuse trace 面板）落 `doc/assets/gifs/`，README 演示注释块随录制解开——依赖真实 key，有条件再录。
- **评估**：金标准集扩 agent 场景用例；改 prompt / 换模型 / 调检索参数后手动 dispatch `ai-eval.yml`（历史 Judge 数字不可引用）。

## 八、双项目分工（不变）

| 时段 | 内容 |
|---|---|
| 2026-09 ~ 2027-01 | EasyOrange 能讲化（§四）；第二项目未启动 |
| 2027-03 起 | 第二项目启动（Python LangGraph 多智能体编排 + 评估，经 MCP 消费本仓库 Java 工具面）——寒假实习延续则顺延 |

**分工边界**（写进两边 README / 简历，防关键词互抢）：EasyOrange = RAG + 单 Agent 深挖 + MCP server + 评估闭环 + 成本/降级治理（Java 工程化叙事）；第二项目 = LangGraph 多智能体 + 差异化场景（Python 为主体，经 MCP 消费 EasyOrange 工具面组成跨语言系统），**不做知识库问答**。

**上下文 / 记忆归属**（防关键词互抢的细化）：单循环内的 token 预算与裁剪、用户画像注入 prompt = **EasyOrange**（生产级单 agent 的上下文治理）；跨节点状态传递 / checkpointer / 子图上下文隔离、跨会话记忆库（LangGraph Store 系）= **第二项目**。一句话口径：EasyOrange 回答「一个 agent 怎么做到生产级」，第二项目回答「多个 agent 怎么编排与评估」。
