## Sprint 分周

### W1-2 多步 Agent 工具循环（easyorange-ai）——已落地（三口径待补，见 W5-6）

- 范围：`AiChatService` 单步 ReAct → 多轮「决策 → 工具 → 观察」循环；步数上限 5；每步 trace 落库（Flyway 新表，V2 起递增）；SSE 事件流加 step 事件（前端步骤可视化）；步数 / 预算超限降级回现有单步
- 工具面：`product_search` / `product_detail` / `knowledge_search`（+ 沿用偏好提取）；现有 4 路并行编排（`AiSearchEnhancerAdapter`）**不删**——与 loop 形成「Workflow vs 自治 Agent」对照，正是 JD 面试原题
- 待补口径：平均步数 / 降级率 / 步级延迟 p95
- 追加（2026-09-19）token 级上下文裁剪已落地：`ChatContextTrimmer`（预算 `easyorange.ai.chat.max-history-tokens` 默认 2000，轮数窗口之上的第二道）+ `TokenEstimator` 估算口径（CJK 0.7 / 其余 0.3 token/字符）；指标 `easyorange.ai.chat.context.tokens`（p50/p95）/ `.trim{action}`（触发率）；**有意不做 LLM 摘要压缩**（步数与轮数上限下收益小、每轮摘要翻倍成本），待补口径：注入 token p50/p95 / 裁剪触发率（关闭 vs 开启两批对比）
- 验收：涉及模块单测 + IT 全绿；`ArchitectureRulesTest` 12 条不破

### W2-3 MCP server——已落地（2026-09-19，演示录屏待补，见 W5-6）

- 已落地：`spring-ai-starter-mcp-server-webmvc` + `@McpTool`，streamable HTTP 端点 `/mcp`（**`protocol` 必须显式配置**——条件装配读 Environment，属性默认值不生效，缺省时端点整个不装配）；工具面 4 个：`search_products` / `get_product_detail` / `list_categories`（新 `CategoryListPort` → `CategoryListAdapter`）/ `search_platform_knowledge`，复用 AssetSourcing / KnowledgeRetrieval / AssetDetail 既有检索服务
- 信任边界（已入 AGENTS.md 硬约束）：**不暴露**订单 / 个人信息 / 写路径——外部 MCP client 无用户上下文；agent 内部工具与 MCP 对外工具面两级暴露、鉴权假设各自独立（匿名可达 + `/mcp` 独立限流 + 防重豁免）
- 验收：Cursor / Claude Desktop 接入文档（README 已就位）+ 演示录屏素材（待录）；e2e 实测 initialize / tools/list / 4 工具调用全通

### W3-4 Langfuse 自托管——已落地（2026-09-19；trace 覆盖率待补，见 W5-6）

- 已落地：compose 自托管 Langfuse v4 六件套（web / worker / clickhouse / postgres / minio / redis，服务名 `langfuse-*` 前缀，profile `langfuse` + `fullstack`，UI :3001——3000 被 Grafana 占用）；后端 trace 桥 Brave → OTel（`spring-boot-starter-opentelemetry`），OTLP 上报 Langfuse；`ChatModelContentObservationFilter` 把 prompt / completion 拷进 `gen_ai.prompt` / `gen_ai.completion` 属性（Langfuse 只认这两个属性键，Spring AI 的 `log-prompt` 产出的是 span 事件、不被消费）；`LANGFUSE_INIT_*` 初始化键与应用 OTLP Basic 认证同源（.env）
- 顺手清理：原 Zipkin 上报是死链路（zipkin-reporter 依赖从未引入、Boot 4 又改名了属性），Zipkin 服务与配置一并移除，traceId 传播改由 OTel 桥承担（MDC / MQ header 链路不变）
- 实测：非流式 + 流式对话多次，**单条 trace 内每步 GENERATION 的 prompt / token / 延迟 / 成本全部可见**（成本按自定义模型价逐调用计算，如 2677 in / 208 out = $0.000928）；模型价经 `/api/public/models` 录入（单位是 per-token，$0.30/1M 要写 3e-7）；流式用量靠 `streamUsage(true)` 末帧回报
- 待补口径：trace 覆盖率；面板截图 / GIF 归 W5-6 录屏
