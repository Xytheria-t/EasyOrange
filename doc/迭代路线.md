## 二、目标（按优先级）

1. **2027 寒假拿到一段远程 AI 应用方向实习**——形态是**长期远程**（寒假起步、开学后延续到 2027-06，每周 8-15h），不是 6 周短工：只有 6 周的岗位几乎投不出去，且「实习中」在春招里比「实习过 6 周」有说服力。
2. **落点保底**：寒假产出一个**开源 merged PR**（Java AI 生态：LangChain4j / Spring AI / MCP Java SDK——与主线同栈、读代码成本最低），不受开学不能延续与春节停摆影响，且公开可验证。
3. **尾部目标（真正的大奖）**：2027 春（3-5 月）投「大二升大三暑期实习」，双项目叙事就位。

## 六、投递与资产口径

**渠道**：BOSS 直聘 + 实习僧（远程标签）为主；牛客 / 即刻 / V2EX 远程板块补充；开源社区里认识的人是内推来源。

**话术骨架**：「大二，远程，寒假每周可投 20h、开学后 15h，能做 6 个月以上」——把「寒假 6 周」说成「长期可延续」，这是岗位池大一个量级的关键。**「开学后能延续」必须先在三、待确认里坐实，不能说没把握的话。**

**匹配策略**：AI 应用 / Agent 方向的中小厂与创业公司为主（一线大厂几乎不做远程）；不限语言投，简历按 JD 微调。

**检索关键词**（2026-09-21 实测一轮）：JD 扫的是**能力词**不是框架名，**岗位名里基本不出现框架名**——Spring AI 是 JD 里的加分项，不是岗位名的主体；岗位名多为复合名（「AI 应用开发工程师（全栈）」「后端开发岗（AI 全栈 / 业务架构）」）。

- **能力词铺量**：`RAG` · `Agent` / `智能体` · `大模型应用开发` · `AI 应用开发` · `Prompt 工程` · `Text-to-SQL` · `知识库` · `向量数据库`
- **框架词精确搜**（带引号）：`"Spring AI"`——能捞到与 EasyOrange 几乎一一对应的少数岗（实测样本要求「基于 Spring AI 构建 Text-to-SQL、RAG 增强、MCP Server」），但以社招 3 年+ 为主
- **不搜** `LangChain4j`：同口径下招聘页出现 **0** 次（教程热度 ≠ 招聘需求），简历关键词不押它
- **语言不筛**：多份 JD 写「Python 或 Java」，也有岗位名写 Java、要求里写「精通 Python」——按能力面匹配，不按语言筛
- **慎投**：JD 标 `OD` 的岗（外包编制，非目标池）

**大厂口径（2027 春投暑期实习时才用）**：大厂 AI 岗分两层——算法序列（Python + 论文 / 竞赛，Java 后端投不进）与**后端开发大类**（AI 全栈当加分项）。**按「后端开发」大类投、AI 工程化当差异化，别按 AI 岗名筛。**

> **依据与局限**：以上来自 2026-09-21 一轮公开检索（BOSS / 智联 / 猎聘 / 牛客可见部分；BOSS、拉勾、51job、猎聘详情页多被 WAF 或登录墙拦截）。唯一可引用的计数是智联「大模型」单页 20 条职位的标题 + 技能标签：Python 7 / 大模型算法 7 / 智能体 5 / Java 2 / LangChain 2 / RAG 2 / **Spring AI 0 / LangChain4j 0**；另有 JD 样本「Java 研发（AI 应用方向）」与「JAVA 及大模型应用开发工程师【实习】」（后者要 vue/h5）。样本极小，**支撑方向判断，不支撑「Java 岗是 Python 的几分之一」这类定量结论**。

**简历**：内容源 = [07 §2.1](interview/07-怎么说.md) 的 bullet 口径（旧壳已归档，只当版式参考）→ 目标版（= [01-备战清单](interview/01-备战清单.md) 的验收清单）→ 投递版（投递前做减法）→ 重渲染（`_shell/print-preview-qa.py`；模板 CSS 在 `~/.agents/skills/asu-skills/assets/frame/asu/base.css`，需与 `icons/`、`logos/` 同目录）。数字一律取工程指标实测值，取不到就不写。

## 八、双项目分工（不变）

| 时段 | 内容 |
|---|---|
| 2026-09 ~ 2027-01 | EasyOrange 能讲化（§四）；第二项目未启动 |
| 2027-03 起 | 第二项目启动（Python LangGraph 多智能体编排 + 评估，经 MCP 消费本仓库 Java 工具面）——寒假实习延续则顺延 |

**分工边界**（写进两边 README / 简历，防关键词互抢）：EasyOrange = RAG + 单 Agent 深挖 + MCP server + 评估闭环 + 成本/降级治理（Java 工程化叙事）；第二项目 = LangGraph 多智能体 + 差异化场景（Python 为主体，经 MCP 消费 EasyOrange 工具面组成跨语言系统），**不做知识库问答**。

**上下文 / 记忆归属**（防关键词互抢的细化）：单循环内的 token 预算与裁剪、用户画像注入 prompt = **EasyOrange**（生产级单 agent 的上下文治理）；跨节点状态传递 / checkpointer / 子图上下文隔离、跨会话记忆库（LangGraph Store 系）= **第二项目**。一句话口径：EasyOrange 回答「一个 agent 怎么做到生产级」，第二项目回答「多个 agent 怎么编排与评估」。
