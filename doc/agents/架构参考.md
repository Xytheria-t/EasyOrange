## 错误码规范

**A/B/C/D 前缀格式**：

| 前缀 | 类型 | HTTP 状态 | 示例 |
|------|------|----------|------|
| A | 成功 / 客户端语义 | 200 / 4xx | A0000=成功, A0401=未登录, A04011=登录已过期, A0403=禁止访问, A0404=404, A0405=405, A0413=上传文件过大, A0429=限流 |
| B | 业务错误 | 400 | B0001=操作失败, B0002=业务异常, B0003=参数校验失败, B0004=请求形态错误（415 等）, B0005 预留 |
| C | 系统错误 | 500 | C0500=服务器内部错误 |
| D | 第三方错误 | 502 | D0502=上游服务不可用（`OrderDomainException.upstream`，支付网关创建失败） |

判断成功：`"A0000".equals(code)`

**A 段编号布局**：A + 4 位 HTTP 状态码 + 可选子码数字（04011 = 401 子码·登录已过期；`SecurityConfig#resolveAuthFailureCode` 按 JWT 过期与否区分 A0401/A04011）。**HTTP 状态由码内数字自动推导**（`IResultCode#resolveStatus` 取 `code[1,5)` 解析，仅接受合法 4xx，否则 400），新增 A04xx 家族码无需改映射。映射单一来源：`IResultCode#resolveStatus(String)` / `#httpStatus()`（common），`GlobalExceptionHandler` 与 `BaseBusinessException#getStatusCode()` 均消费它。

**B 前缀按模块分段**，新增模块优先用保留段：

| 范围 | 模块 | 实现类 |
|------|------|--------|
| B000x | 全局通用 | `ResultCode` |
| B1xxx | user | `UserResultCode` |
| B2xxx | product | `ProductResultCode` |
| B3xxx | order | `OrderResultCode` |
| B4xxx | payment | `PaymentResultCode` |
| B5xxx | file | `FileResultCode` |
| B6xxx | admin | `AdminResultCode` |
| B7xxx | message | `MessageResultCode` |
| B8xxx | ai | `AiResultCode`（B8001 = 日预算超限，映射 **400 不是 429**：429 在前端 `isRetryable` 内会被自动重试，按天耗尽的配额不能复用） |

> 各枚举统一 `@Getter @AllArgsConstructor` 实现 `IResultCode`；预留 B9xxx 给新模块。

## 模块职责边界

**新增代码放哪个模块**：

| 模块 | 能放什么 |
|------|---------|
| easyorange-common | 统一响应体、基础异常、工具类、领域事件接口（`DomainEvent`）、基础枚举 |
| easyorange-framework | Spring/MyBatis/Redis **通用配置**、过滤器、AOP 切面、JWT、全局异常、消息队列（Outbox + DLQ）、UUID v7、分布式锁 |
| easyorange-application | 启动类、全局配置、Flyway 迁移脚本、跨模块适配器（Port 的实现在这里） |
| 各业务模块（user / product / order / payment / message / favorite / ai） | adapter / application / domain 全分层 |
| easyorange-admin | adapter + domain（跨模块走 `Admin*Port`，自身零直接依赖） |

**common 与 framework 的边界**：common 不启动 Spring 上下文（纯定义 + 工具：`Result` / `BizRequire` / `DomainEvent` / `BaseDO` / `PageRequest`）；framework 含 `@Configuration` / `@Service` 与完整生态依赖。**一个类正常运行需要 Spring 容器初始化 → 必须放 framework**。`GlobalExceptionHandler` 在 framework（通用异常映射 + 自动配置全模块生效）；模块特有映射在 `easyorange-application` 加补充处理器（优先级更高）。

`[演进]` **common 拆分**（`common-tech` / `common-domain`）：暂缓——30 个源文件仅 3 个真正属于 domain（`Money` / `DomainEvent` / `DomainEventPublisher`），且 `Money` 依赖 `BizRequire`（技术工具），拆完 domain 侧反而违反「无框架依赖」；100+ 处导入需审查、10+ 模块 pom 需改，收益低于成本。**重新评估时机**：domain 类增长到 10+ 个，或出现明确反模式。

## 模块依赖边

```
application → framework, common, user, product, order, payment, message, favorite
framework → common
user → framework, common
product → framework, common, user       (SellerInfoPort 隔离, optional)
order → framework, common, product, user, payment   (Port 隔离, optional)
payment → framework, common
message → framework, common, user       (UserInfoPort 隔离, optional)
favorite → framework, common, product   (ProductInfoPort / PriceDropNotificationPort 隔离, optional)
ai → framework, common, product         (ProductSearchQueryPort 隔离)
admin → framework, common               (零直接依赖，全部经 7 个 Admin*Port：分类/用户/商品/订单/审核/评价/仪表板)
```

> `BaseDO` / `BaseRepository` / `IdGenerator` / `ConcurrentUpdateException` 已从 framework 下沉到 common——业务模块依赖 framework 是基础设施层面的模块聚合（各模块 `domain/` 不导入 framework 代码），DDD 层约束由 ArchUnit 在包级别守卫。

**跨模块读写分工**：**写操作走 RabbitMQ 事件驱动，查询操作保留同步端口调用**（查询同步的理由：延迟 + 无最终一致窗口 + 无消息积压负担，见 [ADR-0006](../adr/0006-module-decoupling-port-adapter-acl.md)）；订单读侧走自持留痕快照（`eo_order_item.product_snapshot`），不回查商品。

## 事件链路与消费者清单

`DomainEventPublisher` → `ModulithDomainEventPublisher`（`@Primary`）→ Spring Modulith 与应用事务同原子落 `EVENT_PUBLICATION` → 异步发 `eo.domain.events` Topic Exchange（路由键由类名派生，如 `ProductCreatedEvent` → `product.created`）→ 每消费者独占队列 `eo.{name}`，失败进 `eo.{name}.dlq` → `DlqRetryScheduler` 每 5 分钟扫描、按 1/5/15min 指数退避重投（< 3 次），超限转储 `eo.dlq.terminal` 人工介入。at-least-once + `EventIdempotencyChecker` = 精确一次处理。审计日志同走 Outbox（`AuditLogAspect` 发 `AuditLogEvent` → 异步入库）。

**事件消费者**（每模块独占队列）：`ProductEventConsumer`（内部 CQRS 投影）/ `OrderNotificationEventConsumer`（站内信）/ `OrderLifecycleEventConsumer`（取消/退款恢复库存、完成标记售出）/ `PaymentSucceededEventConsumer`（支付成功 → 订单置 PAID 桥接）/ `ProductAuditEventConsumer`（审核通知）/ `WebSocketEventConsumer`（撤回广播）/ `PaymentMetricsConsumer`（支付指标）/ `FavoritePriceDropEventConsumer`（收藏降价提醒）/ `AuditLogEventConsumer`（审计入库）。

**traceId 全链路**：Micrometer Tracing（OTel 桥）`TracingFilter` 提取 HTTP 头 → MDC → `MdcTaskDecorator` 传到 @Async → `EventMetadataMessagePostProcessor` 注入 RabbitMQ message header → 消费者 `EventMetadata.from` decode 回 MDC → 日志 + Micrometer 指标统一关联。

## 异常与校验细则

**异常继承体系**：

```
RuntimeException
└── BaseBusinessException (common，code + message；HTTP 状态码由 GlobalExceptionHandler 按码前缀映射)
    ├── BusinessException (通用业务异常，无自定义子类的模块用它)
    ├── ParamValidationException / FileException (common)
    ├── OrderDomainException / PaymentDomainException / ProductDomainException / MessageDomainException (各模块统一领域异常)
    └── TokenBudgetExceededException (ai；调用方按类型降级)
```

- **每模块一个领域异常类**，具体语义由 `ResultCode` + 类上具名工厂承载（`notFound(id)` / `notOwner(id)`…），构造器非公开。**判据：调用方是否需要按类型分支**（降级 / 重试 / 格式化展示）才值得独立类型，且必须继承本模块统一异常——这样 `catch (XxxDomainException)` 仍兜得住。`TokenBudgetExceededException` 是唯一在用的按类型分支例子。机械门禁：`ArchitectureRulesTest#domain_exception_roots_are_unique_per_module`
- **领域层抛异常后不 try-catch**；应用层通常不处理，让事务回滚，`GlobalExceptionHandler` 在 framework 统一拦截
- **禁止 `static final` 异常实例**——所有抛出点共享同一堆栈，调试困难；每次 `BusinessException.of(...)` 新建实例
- **异常继承**：领域异常必须继承 `BaseBusinessException`（common），其 `getStatusCode()` 委托 `IResultCode.resolveStatus(code)`。`GlobalExceptionHandler` 用 Java 21 模式匹配 switch 在单个 `handle()` 内按类型分发。**禁止抛非 `BaseBusinessException` 子类的 RuntimeException**，否则落 500 兜底（`IllegalArgumentException` 等编程错误一律 500，不做客户端美化）；校验类错误统一 400
- **工厂方法**：`BusinessException` / `FileException` 构造器均 `protected`，统一经 `BusinessException.of(...)` / `FileException.of(...)`；子类正常 `super(...)`
- **模块专属码**：各模块领域异常必须用本模块 `ResultCode`（如 `ProductResultCode.PRODUCT_NOT_FOUND`），**禁止回退全局 `B0002`**
- **方法参数级校验**：控制器**不要**标 `@Validated`——类级 `@Validated` 会让 Spring MVC 内建方法校验失效（`HandlerMethod$MethodValidationInitializer` 见 `@Validated` 即跳过），改由 AOP 抛 `ConstraintViolationException`。两条路径（内建 → `HandlerMethodValidationException` / AOP → `ConstraintViolationException`）都已在 `GlobalExceptionHandler` 映射为 400 + `B0003`，但内建路径是 Spring 6.1+ 推荐做法且不产生控制器 AOP 代理
- **持久化异常在适配器内翻译**：`org.springframework.dao` 家族不得渗进 `domain`/`application`（ArchUnit 守卫）。唯一键冲突等预期内竞争在适配器里翻成端口语义（如 `FavoriteRepository#saveIfAbsent` 返回 `Optional.empty()` 表示"已存在"、幂等成功）；`ConcurrentUpdateException`（乐观锁 0 行命中）、`CannotAcquireLockException`（MySQL 死锁 1213 / 锁等待超时 1205 → 400 + `B0006`）由适配器或全局兜底映射，业务层不 catch 持久层异常

## 已知问题

**OWASP**：硬闸门绿色（CVSS ≥ 8 全部清除）。扫描在 `-Powasp` profile + nightly `security-scan.yml`（`failOnError=false`，NVD 抖动只告警不红，真实 CVSS ≥ 8 仍标红）；**豁免项与理由见** `easyorange-backend/owasp/dependency-suppression.xml`（改豁免须改该文件注释），复跑命令与超时绕法见[常用命令.md](常用命令.md)。

**Redis 连接排查**：`REDIS_PASSWORD` 的 dev 默认值 `easyorange123` 三处对齐（`application-dev.yaml` 占位符默认值 / `.env.example` / `compose.yaml`）；`application.yaml` 的 base 只写 `${REDIS_PASSWORD}`（无默认值），由 dev profile 兜底，避免 prod 拿到弱默认密码。若报 `Unable to connect to Redis`：① `docker compose up -d` 是否启动；② `REDIS_PASSWORD` 是否被设成空值覆盖默认值；③ **YAML 占位符必须 `${VAR:default}`（单冒号）**——写成 bash 风格的 `${VAR:-default}` 会让 Spring 把 `-default` 当字面量，Lettuce 发出的密码多一个前导连字符 → `WRONGPASS`。`compose.yaml` 与 shell 用 `:-` 才正确。
