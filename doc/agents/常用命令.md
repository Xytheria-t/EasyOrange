## 启动开发栈（要「起服务」先看这里，别再逐条命令拼）

> **本项目的所有操作都走命令行**，起服务只认下面这两个入口。逐条拼
> `systemctl start docker` / `docker compose up` / `mvnw package` / `java -jar` / `npm run dev`
> 既慢又零散，不要那么做。

```bash
scripts/dev-up.sh                  # 基础设施 + 后端 + 前端；后端源码无改动则跳过打包
scripts/dev-up.sh --status         # 只报告当前状态，不做任何启停
scripts/dev-up.sh --skip-build     # 直接用已有 jar（后端源码改到一半编译不过时）
scripts/dev-up.sh --no-es          # 不起 ES，省 ~1.0G 常驻内存（搜索/AI 找货不可用）
scripts/dev-up.sh --no-backend     # 只起基础设施 + 前端（后端在 IDE 里跑时用这条）
scripts/dev-down.sh                # 全停（含容器），腾回内存
```

> 每次 `dev-up.sh` 结束会打印一行 `status: frontend=… backend=… elasticsearch=…`，
> 接脚本的一方不必再去 grep 端口判断成没成。
>
> 用户日常**不开**开发栈，`docker.service` 保持 disabled，不要配自启。脚本按需拉起
> dockerd；日志在 `/tmp/easyorange-dev/*.log`，登录账号 `testuser / Password123`。
> 冷启动实测 24~30s（原先手工串行 55~65s）。取舍与踩过的坑见脚本头部注释。

## 常用命令

```bash
# Git 操作（远程 origin = GitHub，push/PR 触发 GitHub Actions）
git push origin develop
git pull origin develop

# 后端构建
cd easyorange-backend && ./mvnw clean package -DskipTests

# 单测（surefire，*Test，快速）
./mvnw test

# 集成测试（failsafe 绑定 verify，*IT）：复用 docker compose dev 栈（MySQL/Redis/RabbitMQ），
# 需先 `docker compose -f compose.yaml up -d`。相比 Testcontainers 不依赖 ryuk sidecar（无代理 Docker 下不会被静默跳过）
./mvnw verify

# 运行特定模块测试
# ⚠️ 单模块 -pl 测试前先 `./mvnw install -DskipTests` 刷新本地仓库，否则按旧已安装 jar 编译，改过的接口签名会假失败（2026-08-12 实测）
# ⚠️ 并发跑 Maven 会撞同一个 target/ 与本地仓库：两个终端 / 两个会话同时 ./mvnw 时表现为随机编译失败，
#    与上一条的「签名假失败」症状难以区分。并行开发要串行化 —— 跑前确认空闲再开：
#    pgrep -f 'classworlds.launcher.Launcher' >/dev/null && echo "忙" || echo "空闲"（2026-09-20 实测）
#    ⚠️ 被 bash -c / 脚本包一层时这条命令会匹配到自己（命令串里含同样的字样），永远显示「忙」；
#       脚本里改用防自匹配写法：pgrep -f "classworld[s].launcher.Launcher"（2026-09-20 实测白等 550 秒）
./mvnw test -pl easyorange-framework
./mvnw test -pl easyorange-admin
./mvnw test -pl easyorange-order
./mvnw test -pl easyorange-message -am
./mvnw test -pl easyorange-product -am

# 生成 JaCoCo 覆盖率报告
./mvnw clean test jacoco:report

# PIT 变异测试（仅 domain 层，HTML 报告 target/pit-reports/index.html）
./mvnw -Ppit test-compile pitest:mutationCoverage
./mvnw -pl easyorange-order -Ppit test-compile pitest:mutationCoverage  # 单模块

# JaCoCo 覆盖率门禁（CI 硬闸门，`-Pci` profile + `-Djacoco.haltOnFailure=true`）
# 默认行≥80%/分支≥60%；adapter 基建重的 application/framework/message/product/user
# 五模块在各自 pom 里按实测校准了更低的**非回归下限**（0.52/0.37 … 0.60/0.50），
# 不是全模块都卡 80/60——逐模块数字与校准口径见 doc/工程指标.md §2.1
# OWASP 依赖安全（nightly security-scan.yml，CVSS ≥ 8 标红）：./mvnw -Powasp verify -DskipTests
# 豁免项见 easyorange-backend/owasp/dependency-suppression.xml

# 文档与代码事实的一致性校验（改代码 / 文档后跑；pre-commit 钩子也跑后两条）
# 走读防漂移：--changed 只核本轮改到的 [doc/interview/02](../interview/02-代码走读.md) 点名类；
# 无参跑默认模式，面试前跑一次
python3 doc/interview/check-drift.py --changed
# 结构计数漂移：核对 doc/工程指标.md 单点区块与代码事实；--fix 自动改写区块
python3 .githooks/check-metrics-drift.py --fix
./mvnw -Pci verify

# 启动开发环境（MySQL + Redis + RabbitMQ，镜像 tag 见 compose.yaml）
docker compose -f compose.yaml up -d

# 重置数据库（DROP/CREATE dev 库与 IT 库 easyorange_it，重启应用即重跑 V1 + 种子；-y 免交互）
scripts/db-reset.sh -y

# 联调 API 请求（查询参数自动 percent-encode；以 { 开头的位置参数当 JSON body；
#   管理端接口需 EASYORANGE_TOKEN，POST /api/auth/login 取 accessToken）
# ⚠️ 不要手写带中文的 URL：Tomcat 11 解析请求行时就把非 ASCII 判为非法，进 Spring 之前就回 400。
#    浏览器会自动编码，所以前端从不出问题；relaxedQueryChars / relaxedPathChars 只覆盖 ASCII，
#    放宽 0x80-0xFF 也无效（实测），别往 server.tomcat 上加配置
scripts/api.sh GET /api/products/search keyword=机械键盘 limit=10
scripts/api.sh POST /api/products/search/record keyword=机械键盘
scripts/api.sh --dry-run GET /api/products/search keyword=机械键盘   # 只打印 curl，不发请求

# ES 搜索（dev profile 默认启用，起后端前必须先起 ES，否则启动期建索引失败）
# compose.yaml 已含 elasticsearch 服务（首次会构建 IK 镜像，略慢）
docker compose --profile search up -d elasticsearch      # 构建并启动 ES（IK 分词，端口 9200）
#   # 手动构建等价命令：
#   docker build -t easyorange-elasticsearch:local infra/elasticsearch && \
#   docker run -d --name easyorange-es -p 9200:9200 -e discovery.type=single-node \
#     -e xpack.security.enabled=false easyorange-elasticsearch:local

# ES 打开后访问 `POST /api/admin/search/reindex`（需 admin token）做全量重建；
# ElasticsearchProductSearchIT（`mvn verify`）会用真实 ES 跑写入→检索→筛选→排序→facet 全链路的回归。

# 后端应用容器化 + 多实例压测栈（Prometheus :9090 + Grafana :3000，dashboard 自动 provisioning）
# 注：app/prometheus/grafana 在 fullstack profile 下——裸 `docker compose up -d` 仍是纯开发三件套，热循环零影响
docker compose --profile fullstack up -d --build --scale easyorange-app=2   # 多实例（nginx 自动 LB；单实例不加 --scale）
docker compose --profile fullstack up -d prometheus grafana                  # 可观测栈（app 未启时显式点名即可，无需 --build）
# 压测：RATE_LIMIT_FILTER_ENABLED=false docker compose --profile fullstack up -d --scale easyorange-app=2
#       k6 run --vus 50 --duration 30s load-tests/product-list.js
# 注意：compose.yaml 新增服务不影响集成测试（application-it.yaml 已用 spring.docker.compose.services 限定 mysql/redis/rabbitmq）

# 一键全栈（后端 + 前端 + 观测 + Langfuse；裸 `docker compose up -d` 仍是纯开发三件套）
docker compose --profile fullstack up -d --build

# 生产部署形态（本仓库只演示与验证，不落清单；被问时口头讲这一套）：
#   镜像 → 私有 Registry（ghcr/ECR）+ imagePullPolicy: Always + cosign 签名
#   编排 → 无状态应用层跑副本（HPA 按 QPS/队列深度，KEDA 或 CPU 70%），中间件全外部化托管服务
#   入口 → Ingress/云 LB + cert-manager 自动 TLS；探针 readiness 摘流量、liveness 不因中间件抖动误杀
#   配置 → 非敏感 ConfigMap、敏感 External Secrets/SOPS + KMS 轮换；JWT 私钥定期轮换
#   存储 → 上传走对象存储（S3/OSS）接 FileStoragePort，避免 RWO PVC 卡多节点
#   可观测 → Prometheus/Grafana/Loki 集中栈 + 业务告警（Down/5xx/P99）

npm test

# 监听模式
npm run test:watch

# 覆盖率报告
```

## IDE 假告警（IDEA）

> 只在 IDEA 里报、`java -jar` 起得来的错误，先当 IDE 模型问题查，别改代码去迁就检查器。

- **`more than one bean of 'XxxPort' type`，且列表里多出来的那个 bean 名就是接口名首字母小写（声明位置指向接口自身）** —— IDEA 的 MyBatis 支持把 `@MapperScan` 的 `basePackages` 下**所有接口**登记成设计期 mapper bean，这条包扫描路径不读 `annotationClass`，所以启动类上 `basePackages = "com.cartethyia.easyorange"` 会罩住全部端口接口（2026-09-29 实测：IDEA 2026.2.2，机制在插件 `intellij.spring.core.analysis.jvm.jar` 的 `SpringMyBatisBeansProvider.processBasePackage`）。
- **判据**：Spring 组件扫描从不把接口当候选组件 —— 给接口加 `@Component`，`findCandidateComponents` 仍只返回实现类（`ClassPathScanningCandidateComponentProvider` 在 easyorange-ai 运行时类路径上实测）；`ObjectProvider<T>` 注入点不报多重候选，所以只经 ObjectProvider 注入的端口（如 `KnowledgeIndexPort`）不会中这条，不能当反例；手写构造器与 Lombok 也不是判据（IDEA 自 2023.2 起在 Lombok 生成的构造器上同样跑注入检查）。
- **处理**：启动类已删 `@MapperScan`（mapper 接口 100% 带 `@Mapper`，由 mybatis-plus starter 按启动类所在包自动扫，注册的就是原来 `annotationClass = Mapper.class` 过滤出的那批）；不要加回来，也不要为消警告加多余 `@Bean`。

## GitHub Issues / PR（gh CLI）

> Issues 与 PRDs 存放在 GitHub issues，全部用 `gh` CLI 读写；repo 由 `git remote -v` 推断，clone 内运行 `gh` 自动处理。

```bash
# 创建 issue（多行 body 用 heredoc）
gh issue create --title "..." --body "..."

# 读取 issue（含 comments 与 labels）
gh issue view <number> --comments

# 列出 open issues（按需加 --label / --state 过滤）
gh issue list --state open --json number,title,body,labels,comments \
  --jq '[.[] | {number, title, body, labels: [.labels[].name], comments: [.comments[].body]}]'

# 评论 / 打标签 / 关闭
gh issue comment <number> --body "..."
gh issue edit <number> --add-label "..." --remove-label "..."
gh issue close <number> --comment "..."

# PR 查看（issues 与 PRs 共享编号空间，裸 #42 先试 pr、失败回退 issue）
gh pr view <number> --comments
```
