## 环境变量

**单一来源**：仓库根 `.env`（gitignored，模板 `.env.example`，两者键保持一致）。**键位与默认值不在此复述，看 `.env.example`**。三类消费者各自原生读取，**无加载库**：

- **Docker Compose**：自动读根 `.env` 做插值；`compose.yaml` 全写 `${VAR:-default}`，无 `.env` 也能零配置启动。集成测试经 `spring-boot-docker-compose` 拉起同一份 `compose.yaml`，走同一插值路径
- **终端 JVM**（`mvnw spring-boot:run` / `java -jar`）：Spring Boot 只认进程环境变量，需先 `set -a; source .env; set +a`；不导入则走 `application*.yaml` 内置默认值
- **IDEA**：默认不读 `.env`；覆盖用 Run Configuration 的 Environment variables 或 EnvFile 插件

仅 prod profile 读取 `SERVER_PORT` / `TRACING_SAMPLING_PROBABILITY`；压测关闭限流用 `RATE_LIMIT_FILTER_ENABLED=false`；AI 的 base-url / model 硬编码在 `application.yaml`（非环境变量）。

> ⚠️ **占位符语法必须区分**：`application*.yaml` 用 `${VAR:default}`（单冒号）；`compose.yaml` 与 shell 用 `${VAR:-default}`（`:-`）。YAML 里误写 `:-` 会让 Spring 把 `-default` 当字面量默认值（Redis 密码多一个前导连字符 → `WRONGPASS`）。

> **dev seed 账号**：`db/dev/R__insert_dev_test_data.sql` 中所有账号共用同一 bcrypt 哈希，明文密码统一 **`Password123`**（admin / testuser / liming 等，压测脚本已对齐）。登录失败 5 次触发 Redis 登录锁 30 分钟，清 `eo:user:login:attempts:<identifier>` 解锁。

## 后端约定

- **多模块构建**：改子模块后启动前必须先 `./mvnw install -DskipTests`（或 `clean package -pl <module> -am`），否则按旧已安装 jar 编译，改过的接口签名会假失败
- **启动方式**：统一 `./mvnw spring-boot:run -pl easyorange-application`。JVM 参数由 `easyorange-application/pom.xml` 的 `<jvmArguments>` 管，环境变量走 `.env` / shell export。**IDE 调试必须把 JVM flag 手动补进 VM options**（pom 的 jvmArguments 不传给 IDE）；禁止终端 / IDE 混跑同一份代码
- **父 POM 模块注册**：新增后端子模块必须在 `easyorange-backend/pom.xml` 的 `<modules>` 注册
- **Mockito Java 25 兼容**：已配 `mock-maker-subclass` 模式，**新测试不要改回 inline**（WSL2 下 ByteBuddy attach 会失败）
- **集成测试不用 Testcontainers**：`*IT` 继承 `AbstractIntegrationTest`，基础设施由 `spring-boot-docker-compose` 复用根 `compose.yaml`（start-only）提供，failsafe 绑定 `mvn verify` 真实连 MySQL/Redis/RabbitMQ。不要自己搭 `@Testcontainers`（ryuk sidecar 在无代理 Docker 下拉取失败会让用例**静默跳过**，掩盖装配错误，见 [技术债务清单 TD-001](../技术债务清单.md)）。ECC `java/testing.md` 的 Testcontainers 建议在本仓库不适用
- **`product-paths` 白名单陷阱**：`security.product-paths` 跳过 JWT 认证且前缀匹配（`/api/products` 会匹配 `/api/products/my`）。新增需认证接口必须补更精确的 `.requestMatchers(GET, "/api/products/my/**").authenticated()`
- **LoginCredential sealed interface**：登录凭据用 `sealed interface LoginCredential`（`domain/valueobject/`），新增登录方式加新 `record` 实现，禁止用枚举字段区分
- **RabbitMQ Spring AMQP 4.0.x API**：`CorrelationData` 在 `org.springframework.amqp.rabbit.connection`；`ReturnsCallback.returnedMessage()` 收 `ReturnedMessage` 对象；concurrency 用 `concurrent-consumers` + `max-concurrent-consumers`（不支持 `"1-5"` 范围格式）
- **ConfigurationProperties 注册方式**：统一 `@ConfigurationProperties` + `@ConfigurationPropertiesScan`，Properties 为 record（构造器绑定，不加 `@Component`），已注册的不要再加 `@EnableConfigurationProperties`；默认值用 `@DefaultValue`（标量）/ 紧凑构造器（集合与嵌套 record）。record 是 final 类，subclass MockMaker 下无法被 Mockito mock，测试用 `PropertyBindings` 夹具构造
- **Flyway SQL 格式**：CREATE TABLE 列定义禁止对齐格式，必须紧凑，否则 MySQL 1064 语法错误
- **注册昵称默认值**：注册时 `nick_name` 默认等于 `username`，禁止随机昵称逻辑

## 前端约定

- **管理端弹窗 / 抽屉必须 Portal**：`src/admin/` 下所有 Modal / Drawer / 确认框必须 `createPortal(..., document.body)`。原因：`.admin-sidebar` / `.admin-header` 的 `backdrop-filter: blur()` 创建新包含块，`position: fixed` 定位基准会错乱。居中统一 `position: fixed; left: 50%; top: 50%; transform: translate(-50%, -50%)`
- **弹窗内容溢出**：Portal 容器必须 `maxHeight: 'calc(100vh - 2rem)'` + `display: flex; flexDirection: column; overflow: hidden`，内容区 `flex: 1; overflowY: auto; minHeight: 0`
- **`AdminTable` render 签名**：`(value, record)`——第一个参数是单元格值，第二个才是整行。只写 `(record) => ...` 会拿到 `undefined`
- **管理端样式**：`src/admin/` 下必须内联 `style={{}}`，禁止依赖外部 CSS（唯一例外 `src/admin/styles/admin.css`）
- **管理端下拉菜单**：所有 `<select>` 必须用 `AdminSelect` 组件（Portal 渲染面板，解决 fixed 定位失效）；`handleClickOutside` 必须同时排除触发按钮 ref 和列表 `listRef`，否则点选项会立即关闭
- **管理端页面布局**：三层结构——根 `position: relative, minHeight: 'calc(100vh - 80px)'`；背景层 `position: absolute, inset: 0, borderRadius: 20`（禁 fixed）；内容层 `position: relative, zIndex: 1, display: flex, flexDirection: column`
- **管理端路由**：`admin/*` 路由必须在 `MinimalLayout` 外部独立渲染，否则 C 端 Header 会出现在管理页
- **重依赖懒加载**：体积 > 100KB 的第三方库（recharts / dayjs / monaco-editor / xlsx / @tiptap/*）必须 ① `manualChunks` 分独立 `vendor-*` chunk ② `React.lazy` + `Suspense` 包装。参考 `src/admin/pages/dashboard/charts/lazyCharts.tsx`
- **CSS 导入**：共享组件（如 `ProductCard`）的样式 CSS 必须在组件文件自身 import，禁止只靠页面级导入（React.lazy 懒加载时页面级 CSS 不随组件 chunk 加载）
- **Zustand 写入**：store **只接受事件驱动写入**（STOMP 回调、用户操作回调），**禁止在 `useEffect` 内写 store**（spread 新引用 → 重渲染 → 无限循环）
- **Zustand selector**：`?? []` / `?? {}` 必须用模块级常量，禁止内联（新引用触发无限循环，React 19 StrictMode 下放大到 50 层）
- **聊天 conversationId 格式**：排序双 ID `conv_{minId}_{maxId}`，保证 A→B 与 B→A 一致
- **`scrollIntoView` 防误触发**：用 ref 记录上一次状态（如历史长度），仅在数据真正新增时滚动，禁止在仅依赖 props/state 的 effect 里无条件调用
- **Long → String 收敛**：后端全局把 `long`/`Long` 序列化成字符串（JS 精度安全，见 `JacksonConfig`），计数字段线上是 `"3"` 而非 `3`（含 `PageResult.total`）。前端 API 层声明为 `number` 的计数字段必须 `Number(...)` 收敛（参考 `favoriteApi.getCount()`），否则算术会变拼接
- **行为准则**：通用编码行为准则（KISS/DRY/YAGNI、外科手术式改动、先思考后编码）由 karpathy-guidelines 技能与 ECC `common/coding-style.md` 自动加载
