### 命名与术语

- ai 模块新增类型不再带 `Ai` 前缀。保留例外：`AiProperties` / `AiPricingProperties`（配置前缀惯例）、`AiResultCode`（全仓 `*ResultCode` 惯例）、`AiAdmin*Controller`（`Admin*` 前缀专属 easyorange-admin）、`AiHealthIndicator`（去前缀与框架接口撞名）。
- 循环术语单点在 [领域参考](领域参考.md)：round=决策轮、step=工具调用、turn=对话轮、call=模型调用；指标与文档口径以此为准。
- 三层名字不可混：`RoundDecider`（内核每轮契约）、`ToolCallDecider`（调模型的决策器）、`ToolCallDecision`（一次决策的解析视图）。
- `ModelCaller`（发起）/ `ModelCallScope`（记账场景）/ `ModelCallRecorder`（记账）三者同族；`support` 包名保留——Spring 生态（`org.springframework.ai.support`）同款，包内是模型管道/预算/安全/检索观察，叫 `model` 失真。
- 路由键按模型角色：`decision` / `vision` / `judge`，不按业务链路。prompt 名 `ai_chat_tool_system` 是模板名，与路由键无关，不要跟着改。
- 标识符跟 Spring / Java 生态先例取形（`allowedTools`，不回退 whitelist）；中文注释继续用「白名单」不算冲突。
- 冻结契约：指标 tag 值（`step_limit` 等）、`eo_tool_call_step_trace` 表名、工具名、V1 迁移注释字节（Flyway checksum）、`prompts/*.yml` 面向模型的正文。

### 评审定论（不要再动）

- `Spec` 十字段不拆、名字保持 `Spec`：全仓仅 2 个构造点、整包传递；面试口径 = 与 `Outcome` 是 spec/status 同构。
- `finish` 命名保留：ReAct 血统 + 决策/生成分离，改名波及 golden-set / 双 prompt / trace 历史。
- `executeCalls` 的 finish 分区设计定稿：finish 先摘出 → 执行循环无 skip 分支；同轮兄弟照跑、finish 记最后；`nextStepIndex = firstStepIndex + toolPath.size()` 是契约。
- 预算装配已单点化：`application/support/TokenBudgetGuard`（resolve / tryReserve / exhausted）收口「配置优先、兜底其次」；`ChatBudgetGuard` 是 chat 场景薄壳。**不要再提合并这三个类。**
- 白名单唯一判定点 `Input.allows(toolName)`；`ToolCallStep` / `ToolCallDecision` 双 record 拆分保留（内核只消费 5 分量）。
- `RoundDecider` 的 SAM 这层保留：单实现接口换的是「内核零知识」，出现第二种决策机制（规则决策 / 多模型投票）再回看。
- 不再加 Spring AI getter 防御判空：以 spring-ai 2.0.1 的 `@NullMarked` 注解契约为准；全后端死代码普查结果为 0，别重扫。
- 单轮工具并行与决策自修复暂不做（收益被逐轮模型延迟淹没）；`ModelCaller` / `ModelRouter` 已全量审计，无精简项。
- 记账摘要必须覆盖真实输入内容（`eo_ai_call_log.prompt_hash` 用于去重与回归）；唯一例外是视觉调用，只摘要文本部分。
- `ModelCallScope`（记账轴，按业务链路）与 `ModelRouter.SCENARIO_*`（路由轴，按模型角色）刻意不合并；`ToolCallDecider.decideOnce` 里「scope 注入 / 路由角色写死」的不对称是判据产物，不是疏漏。
- 评过、明确不动：`RetrievalEvalRun.createdAt` 保持 String；`PlatformMcpTools` 的 `@McpToolParam` 保持 required；`GoldenSetExportService` 抛 `BusinessException` 不带 cause。

### 工程陷阱

- Spring Modulith 属性名以 jar 内 `META-INF/spring-configuration-metadata.json` 为准：`jdbc.schema-initialization.enabled` 是点分、`staleness.check-intervall` 上游就是双 L；宽松绑定对拼错的键静默失效。
- Spring Framework 7 的 `org.springframework.http.HttpMethod` 是 value class 不是 enum，配置项保持 `String` + `equalsIgnoreCase`，改成枚举类型得不到 fail-fast。
- 注解元素 javadoc 禁 `@param`（doclint error、IDEA 标红）：用散文 `{@code x}` 或元素级 `@return`。
- javadoc `{@link}` 跨层时用全限定名，别为消红给下层加跨层 import；同层（domain → domain）用 import 才是正确处置。

### 运行态与工作流

- 后端 `./mvnw spring-boot:run -pl easyorange-application` → :8080；前端 `npm run dev` → :5173（Vite 代理 `/api`、`/ws`）。查活 `ss -tlnp | grep -E ':(5173|8080)'`，停止 `fuser -k 5173/tcp 8080/tcp`。应用在终端跑着时别用 IDEA 再起同一应用。
- 后台 job 在 worktree 完成后 `ExitWorktree(keep)` → 主检出 `git merge --ff-only`（提交目标见下方「提交规范」）；**不要主动 push**——含 `easyorange-ai/**` 会触发 ai-eval 的真实模型调用。
- worktree 里 pre-commit 读的是主检出（`core.hooksPath` 是绝对路径）；`check-doc-links.py` 在 worktree 会因 `SKIP_DIRS` 含 `.claude` 而静默空转，假绿。
- 并行任务撞车：先 `git worktree list` + `git log <其分支>`；主检出 ff 报 Diverging 就回 worktree rebase，**重跑 verify** 再 ff。
- 小修读法：点名文件 → 只读该文件 + 直接依赖 + 对应测试；只给症状 → 一次精准 rg；大面积探索交子代理；只跑改动模块的测试，收口再全量。
- 本仓 `.claude/settings.json` 常驻 `{"worktree":{"bgIsolation":"none"}}`（被 `.gitignore` 的 `.claude/*` 覆盖），后台对话可直接改共享检出；大改仍走 worktree 纪律。
- 网络：GitHub 优先直连并加 `-c http.version=HTTP/1.1`；Windows 梯子对 github 的 TLS 隧道会被掐，先直连试，单次失败 `timeout 45` 重试。
