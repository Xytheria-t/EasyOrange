# 数据合规基线

> 面向 EasyOrange 的 C2C 资产流转 + 支付 + 实时聊天 + AI 生成内容场景。本文记录代码层与运维层必须遵守的**数据合规约束**，作为 `doc/架构/` 的补充。适用于《个保法》《数据安全法》及一般企业数据治理基线。

## 1. 数据面盘点

| 数据 | 类型 | 涉及模块 | 敏感性 |
|------|------|---------|--------|
| 用户注册信息（用户名/手机号/密码哈希） | PII | user | 高 |
| 实名/收货地址/联系电话 | PII | user/order | 高 |
| 订单/支付/退款记录 | 个人交易数据 | order/payment | 高 |
| 聊天记录（点对点） | PII + 通信内容 | message | 高 |
| AI 生成内容（估值/审核/文案/客服） | 生成内容 | ai | 中 |
| 商品/资产信息 | 业务数据 | product | 低-中 |
| 浏览/搜索历史 | 行为数据 | product | 中 |

## 2. 审计日志（关键写操作可追溯）

已有：`easyorange-framework/.../audit/`（`AuditLogAspect` + `AuditLogService` + `AuditLog` 实体 + DLQ 事件消费）。

**基线要求**
- 关键写操作必须落审计：**支付创建/成功/失败/退款、订单状态变更、提现、账号密码/手机号变更、删除请求权执行**。
- 审计记录至少含：操作者 userId、操作类型、资源 id、结果、时间、traceId（与全链路可观测关联）。
- 审计日志不可由普通用户篡改/删除（运营侧独立权限）。
- **禁止**将密码、令牌、完整手机号等敏感值写入审计日志——只记脱敏值或哈希。

## 3. PII 处理约束

### 3.1 脱敏（代码层）
- **手机号/电话**在视图层（VO/响应）输出时脱敏：`138****8000`。
- **收货地址**在非必要视图（如订单详情给卖家看）脱敏到城市级。
- 当前无统一 `MaskUtil` —— 新增敏感字段输出前必须过脱敏工具，禁止直接序列化完整 PII。
- 日志（logback）默认脱敏：敏感字段不入 `%msg`，必要时用占位符。

### 3.2 密码与令牌
- 密码仅存 `BCryptPasswordEncoder` 哈希（已实现），禁止明文/可逆加密。
- Refresh token 仅存 SHA-256 哈希（已实现，见 `RefreshTokenStoreImpl`）。
- Access token 会话敏感，不入日志、不入本地存储（前端走 HttpOnly cookie 的 refresh，access 走内存）。

### 3.3 数据最小化
- 接口只返回当前业务所需字段，禁止整表序列化。
- 聊天/搜索历史等行为数据按需采集，不无限留存。

## 4. 保留期限与删除请求权

| 数据 | 建议保留期 | 删除策略 |
|------|-----------|---------|
| 聊天记录 | 交易存续期 + 90 天 | 用户删除后异步清理（message 模块） |
| 搜索历史 | 30 天 | 定时清理（`SearchHistoryBuffer` 已有缓冲队列） |
| 支付/订单 | 法定账务留存期（≥5 年） | 不物理删除，逻辑删除 + 访问受限 |
| 审计日志 | ≥180 天 | 归档到冷存储 |

**删除请求权**：用户请求删除账号时，必须级联删除/匿名化其可标识数据（聊天、收货地址、实名信息），仅在法律要求下保留账务记录并脱敏关联。

## 5. 传输与存储加密

- 传输：生产 HTTPS（`verifyServerCertificate=true`、refresh cookie Secure、HSTS 已配置）。
- 存储：DB 连接生产走 SSL（`useSSL=true`）；Redis 生产 `ssl: true`。
- 敏感字段列级加密（如支付钱包 PIN）如需落地，用 `@ColumnTransformer` 或应用层加密服务，密钥走 `SecretService`。

## 6. 密钥与访问控制

- 密钥统一经 `com.cartethyia.easyorange.config.secret.SecretService` 解析（当前 env 实现；Vault/KMS 接入点）。
- 生产启动 fail-fast（`SecretValidationRunner`）缺失密钥即中止。
- 管理后台/admin 接口必须 RBAC 鉴权（`@PreAuthorize`），禁止越权访问他人数据。
