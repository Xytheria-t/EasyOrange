## 二、部署架构

### 开发环境（docker-compose）

```
docker-compose.yml
├── mysql:8.4              → 端口 3306, 内存限制 1G
├── redis:7.4-alpine         → 端口 6379, 内存限制 512M, 密码 easyorange123
├── rabbitmq:3.13-management → 端口 5672(AMQP)/15672(管理UI), 内存限制 512M
├── elasticsearch:8.17.3     → 端口 9200, 内存限制 1G, 含 IK 分词器（可选）
└── 应用本地运行            → 端口 8080
```

### 生产环境（Docker 多阶段构建）

```
Dockerfile（多阶段构建）
├── 构建阶段: eclipse-temurin:25-jdk-alpine
└── 运行阶段: eclipse-temurin:25-jre-alpine
    ├── 非 root 用户（easyorange）
    ├── ZGC + Generational GC
    ├── 健康检查: /actuator/health
    └── 优雅停机: 90s timeout
```

### 可观测性

| 组件 | 用途 | 端点/配置 |
|------|------|----------|
| Spring Actuator | 健康检查、指标暴露 | `/actuator/health`, `/actuator/prometheus` |
| Micrometer + Prometheus | 指标采集和存储 | `micrometer-registry-prometheus` |
| Logstash Logback Encoder | 结构化 JSON 日志 | 生产环境自动启用 |
| Docker HEALTHCHECK | 容器健康检查 | 30s 间隔，60s 启动等待 |

## 三、模块总览

| 模块名 | DDD 架构角色 | 核心定位 | 能放什么 |
|-----------|------------|---------|---------|
| easyorange-backend | 父工程（Parent POM） | 全局依赖 / 版本管理 | 统一依赖版本号、插件管理、模块聚合 |
| easyorange-common | 通用基础模块 | 所有模块可依赖 | 统一响应体、基础异常、通用工具类、领域事件基类、基础枚举 |
| easyorange-framework | 框架适配层 | 基础设施通用封装 | Spring/MyBatis/Redis **通用配置**、过滤器、AOP 切面、JWT 工具、全局异常处理器、**RabbitMQ 消息队列（Topic Exchange + RoutingKey + 可靠性回调）**、分布式 ID 雪花算法、一致性哈希 |
| easyorange-message | 消息业务模块 | 站内信/通知限界上下文 | 消息实体、消息模板、离线消息、WebSocket、订阅管理 |
| easyorange-application | 启动聚合层 | 主入口 | 启动类、全局配置、Flyway 迁移脚本 |
| easyorange-user | 用户限界上下文 | 完整 DDD 业务模块 | adapter/application/domain 全分层 |
| easyorange-product | 商品限界上下文 | 完整 DDD 业务模块 | adapter/application/domain 全分层 |
| easyorange-order | 订单限界上下文 | 完整 DDD 业务模块 | adapter/application/domain 全分层 |
| easyorange-payment | 支付限界上下文 | 完整 DDD 业务模块 | adapter/application/domain 全分层 |
| easyorange-favorite | 收藏限界上下文 | 完整 DDD 业务模块 | adapter/application/domain 全分层（DDD 六边形架构（port + repository 隔离）） |

### 模块演进规划 `[演进]`

当前 `easyorange-common` 承担了技术工具和领域共享两重职责。随着业务增长，可拆分为：

| 演进后模块名 | 定位 | 内容 |
|-------------|------|------|
| easyorange-common-tech | 纯技术通用底座 | 纯 JDK 工具类、统一响应体、基础异常、纯技术常量（无框架/中间件依赖） |
| easyorange-common-domain | 领域共享内核 | 共享值对象、领域事件基类、聚合根基类、全局业务枚举 |

拆分判断标准：当 `common` 模块中领域相关代码（值对象、领域事件基类、业务枚举）占比超过 30%，或业务模块需要仅依赖领域部分而排斥技术工具时，启动拆分。

## 四、模块依赖关系

### 当前依赖现状 `[现状]`

```
common ← framework ← user ← product ← favorite
                         ↑         ↑
                         └── order ┘
                              ↑
                         payment ← order
                         message ← user

application ← 所有业务模块（聚合启动）
```

**实际 Maven 依赖**：

| 模块 | 依赖 |
|------|------|
| easyorange-common | Lombok, Jackson, Commons Lang3, SLF4J, Spring Core/Web, Jakarta Validation, MyBatis-Plus Extension |
| easyorange-framework | common, Spring WebMVC, Spring Security, Spring Redis, Spring AMQP, JJWT, AspectJ, SpringDoc, MyBatis-Plus, Logstash, Micrometer, Caffeine, Thumbnailator |
| easyorange-user | framework, MapStruct |
| easyorange-product | framework, **user** |
| easyorange-order | framework, **product, user, payment** |
| easyorange-payment | framework |
| easyorange-message | framework, **user**, Spring WebSocket |
| easyorange-favorite | framework, **product** |
| easyorange-application | framework, user, product, favorite, order, message, Actuator, Prometheus, Flyway, MySQL |

### 依赖规则与演进目标

**目标铁律**：业务模块之间禁止直接依赖，跨模块通信通过事件驱动或端口抽象实现。

**演进状态 (2026-05-09)**：

| 依赖 | 状态 | 实现方式 |
|------|------|---------|
| order → product | ✅ 已隔离 | `ProductQueryPort` + `ProductInventoryPort`，适配器在 application 模块 |
| order → user | ✅ 已隔离 | `UserInfoPort`，适配器在 application 模块 |
| order → payment | ✅ 已隔离 | `PaymentGatewayPort` + 事件驱动 (`PaymentInitiationRequestedEvent`) |
| product → user | ✅ 已隔离 | `SellerInfoPort`，适配器在 application 模块 |
| message → user | ✅ 已隔离 | `UserInfoPort`，适配器在 application 模块 |
| favorite → product | ✅ 已隔离 | `ProductInfoPort`，适配器在 application 模块 |

**已完成的演进**：

1. ✅ **短期**：端口接口 + 适配器模式隔离，Maven 依赖标记为 `<optional>true</optional>`
2. ✅ **中期**：写操作改为 RabbitMQ 消息队列驱动（Topic Exchange + Quorum Queue + 手动 ACK），查询操作保留同步端口调用。通过 `@ConditionalOnProperty` 支持双模式切换（RabbitMQ / 原有 EventBus）

**架构守卫**：`ArchitectureRulesTest.java` 验证端口接口必须有适配器实现
