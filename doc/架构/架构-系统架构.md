## 二、模块职责边界

各模块的定位与 DDD 角色见 [README 模块结构表](../../README.md#模块结构)；下面是**新增代码该放哪个模块**的判据：

| 模块 | 能放什么 |
|-----------|---------|
| easyorange-backend | 统一依赖版本号、插件管理（父 POM） |
| easyorange-common | 统一响应体、基础异常、工具类、领域事件接口（`DomainEvent`）、基础枚举 |
| easyorange-framework | Spring/MyBatis/Redis **通用配置**、过滤器、AOP 切面、JWT、全局异常、消息队列（Outbox + DLQ）、UUID v7、分布式锁 |
| easyorange-application | 启动类、全局配置、Flyway 迁移脚本、跨模块适配器（Port 的实现在这里） |
| 各业务模块（user / product / order / payment / message / favorite / ai） | adapter/application/domain 全分层 |
| easyorange-admin | adapter + domain（跨模块走 `Admin*Port`，自身零直接依赖） |

`[演进]` **common 拆分**：当 common 中领域相关代码（值对象、事件接口、业务枚举）占比超 30%，或业务模块需要只依赖领域部分而排斥技术工具时，拆为 `common-tech`（纯 JDK 工具/响应体/基础异常）+ `common-domain`（共享值对象、`DomainEvent`、聚合根基类）。当前评估结论是暂缓，理由见 [架构-部署.md](架构-部署.md) §三。

## 三、六边形分层与包结构

所有业务模块统一遵循「adapter（inbound / outbound）→ application → domain」的扁平结构：

```
<module>
├── adapter/inbound/          # 外部 → 模块：web（controller/dto/validation）、messaging（消费者）、job（定时任务）
├── adapter/outbound/         # 模块 → 外部：persistence、cache、elasticsearch、scheduler、messaging
├── application/              # 用例编排：service / command / query / dto / assembler
├── domain/                   # 领域层：aggregate / valueobject / service / event / port / repository / constant / exception
└── config/                   # 模块内基础设施关注点（Bean 注册等）
```

| 约定 | 规则 |
|---|---|
| 出站端口 | 平铺在 `domain/port/`（不用 `output/` 子包）；`domain/repository/` 是特殊出站端口，专用于聚合根存取 |
| 领域常量 | 放 `domain/constant/`；**技术常量**（路由前缀 / 缓存 Key / MQ Topic）下沉到对应适配器层 |
| 领域服务 | 不用 `@Service` 等框架注解，由 `config/` 下的配置类手动注册 Bean |
| 领域服务依赖外部功能 | 通过端口接口抽象，由适配器层实现 |
| 已废弃 | `infrastructure/` 包（ArchUnit 对任何新建 `infrastructure/` 路径报错）、无分层的 `service/` / `entity/` / `dto/` 目录 |

**应用服务按职责聚合**：多个用例共享相同依赖集与事务边界时合并到同一应用服务（如 `AuthAppService` 处理注册/登录/登出/刷新/忘记密码/修改密码）；差异大或可能独立演进时再拆。判据：**一个应用服务的构造函数变更不应强迫修改不相关的调用方**。

**DTO 分层放置**：被 `application`（assembler / service）和 `adapter`（controller）共同引用的 Response/DTO 必须放 `application/dto/`，禁止放 `adapter/inbound/web/dto/response/`——application 依赖 adapter 违反依赖倒置。仅 controller 单独使用的响应 DTO 可留在 adapter 层。

### common 与 framework 的边界

| 维度 | common | framework |
|------|--------|-----------|
| 依赖范围 | JDK + Jackson + Spring Core/Web + MyBatis-Plus Extension + SLF4J + Jakarta Validation | Spring 完整生态 / Redis / MQ / MyBatis-Plus Starter |
| 内容类型 | 基础定义、工具类、异常定义、枚举 | 配置类、过滤器、AOP 切面、安全拦截、服务实现 |
| 典型类 | `Result`、`BizRequire`、`DomainEvent`、`BaseDO`、`PageRequest` | `RedisConfig`、`SecurityConfig`、`GlobalExceptionHandler` |
| 是否启动 Spring 上下文 | 否（纯定义和工具） | 是（含 `@Configuration`、`@Service`） |

**迁移规则**：一个类正常运行需要 Spring 容器初始化（注入 Bean、用 `@Configuration`）→ 必须放 `easyorange-framework`。

**GlobalExceptionHandler 的定位**：放 framework，因为它处理所有模块通用的异常映射（`BusinessException` → HTTP 响应）、依赖框架层异常类型（Spring Security / Validation），并经 Spring Boot 自动配置全模块生效。若未来需要模块特有映射，在 `easyorange-application` 加补充处理器（优先级高于通用处理器）。

> `PageRequest`（`common/dto/`）是纯 JDK + Jakarta Validation 模型。**领域模型不共享 MyBatis-Plus 的 `IPage`**：分页参数在 common 定义、在 framework 的适配器层翻译成 MyBatis-Plus 分页对象。

## 四、模块依赖规则

- **依赖方向单向向内**：domain → application → adapter（domain 零框架依赖，由 ArchUnit 守卫）
- **跨模块依赖一律 `<optional>true</optional>`**：编译期隔离；跨模块调用只经 Port/ACL 适配，禁止直接依赖其他模块的领域模型或 Mapper。门禁：`.github/scripts/check-optional-deps.py`（除组合根 `easyorange-application` 外，领域模块互相依赖必须 optional，违规即 CI 失败）
- **端口必有适配器**：ArchUnit 校验「定义了 Port 但无实现」的悬空端口
- **敏感操作要求 `reason` 字段**：管理端订单干预、角色切换等必须带理由（落审计日志）

### 依赖现状 `[现状]`

| 依赖 | 状态 | 实现方式 |
|------|------|---------|
| order → product | ✅ 已隔离 | `ProductInventoryPort`（下单校验 / 扣减 / 恢复库存 / 标记售出）；订单展示读自持留痕快照，不回查商品 |
| order → user | ✅ 已隔离 | `UserInfoPort` |
| order → payment | ✅ 已隔离 | `PaymentGatewayPort` 同步调用（本地单事务内建支付记录，[ADR-0007](../adr/0007-order-local-tx-over-saga.md)） |
| product → user | ✅ 已隔离 | `SellerInfoPort` |
| message → user | ✅ 已隔离 | `UserInfoPort` |
| favorite → product | ✅ 已隔离 | `ProductInfoPort` |

**依赖规则与演进目标**：业务模块之间禁止直接依赖——**写操作走 RabbitMQ 事件驱动，查询操作保留同步端口调用**（查询同步的理由：延迟 + 无最终一致窗口 + 无消息积压负担，见 [ADR-0006](../adr/0006-module-decoupling-port-adapter-acl.md)）。

**跨模块读写示例**（product → user）：`SellerInfoPort` 端口 + `SellerInfo` 值对象隔离，适配器实现在 `easyorange-application` 模块；order 对 product / user / payment 的 Maven 依赖全为 `<optional>true</optional>`，业务逻辑完全经端口 + 适配器隔离。

### 模块级约定

**事务**：查询方法必须标 `@Transactional(readOnly = true)` 以启用数据库只读优化。

**缓存**：所有业务模块的缓存适配器必须——

1. **端口定义在 `domain/port/`**（如 `OrderCachePort`、`ProductCachePort`）
2. **实现放 `adapter/outbound/cache/`**（如 `RedisOrderCacheAdapter`、`ProductCacheAdapter`）
3. **禁用 `infrastructure/` 包**（ArchUnit 对新建路径报错）
4. **技术常量下沉到适配器层**：Redis Key 前缀、过期时间放 `adapter/outbound/cache/` 下的常量类
5. **应用层只依赖端口**：通过端口接口操作缓存，不直接依赖 `RedisTemplate`
