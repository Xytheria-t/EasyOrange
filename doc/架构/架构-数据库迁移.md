# EasyOrange 数据库迁移规范

> Flyway 的流程规范在本文。**表结构的单一事实来源是迁移脚本本身**；全局约定（主键策略 / 公共字段 / 索引与数据类型规范 / 表清单）见 [DATABASE.md](../DATABASE.md)。

---

## 一、核心原则

| 原则 | 说明 |
|------|------|
| **DDL 与 DML 分离** | 结构变更（V 前缀）与参考数据（R 前缀）必须分开成独立迁移文件 |
| **迁移不可变** | 已部署的 V 版本迁移禁止修改，只能新增 |
| **自包含迁移** | 一个功能一个迁移文件，含该功能所需的完整结构（建表、索引、约束）；不按"索引层/约束层"拆分 |
| **可重复数据** | 参考数据用 `R__` 可重复迁移，按业务域独立拆文件 |
| **紧凑格式** | CREATE TABLE 列定义**禁止对齐填充**（列名与类型间大量空格会让 Flyway MySQL 解析器报 1064） |

## 二、文件布局与命名

```
db/migration/
├── V1__init_schema.sql        # DDL: 初始表结构（开发阶段合并后的完整当前 DDL）
├── V{N}__{feature}.sql        # DDL: 后续变更（ALTER TABLE / CREATE TABLE），功能驱动命名
└── R__seed_{domain}.sql       # DML: 参考数据（分类 / 知识库种子…），一域一文件，可重复执行
db/dev/
└── R__insert_dev_test_data.sql  # DML: 开发测试数据，仅 dev 加载
```

当前脚本清单见 [DATABASE.md](../DATABASE.md)。

**`R__` 可重复迁移原则**：必须用 `ON DUPLICATE KEY UPDATE` 保证幂等；必须包在 `START TRANSACTION` / `COMMIT` 中；频繁更新的 DML 优先用 R__，避免堆空版本号。

## 三、DDL 编写规范

**索引、约束内联在 CREATE TABLE 里**（不在建表后追加）：

```sql
CREATE TABLE `eo_product_review` (
    `id` VARCHAR(36) NOT NULL COMMENT '主键 ID',
    `rating` TINYINT NOT NULL DEFAULT 5 COMMENT '评分（1-5）',
    `create_time` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    `del_flag` TINYINT NOT NULL DEFAULT 0 COMMENT '删除标志（0 正常 1 删除）',
    `version` INT NOT NULL DEFAULT 0 COMMENT '乐观锁版本号',
    PRIMARY KEY (`id`),
    KEY `idx_eo_product_review_product_status_del_time` (`product_id`, `status`, `del_flag`, `create_time` DESC),
    CONSTRAINT `chk_eo_product_review_rating` CHECK (`rating` >= 1 AND `rating` <= 5)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci COMMENT='商品评价表';
```

**ALTER TABLE**：同表的多个操作合并成一条语句，顺序 `DROP CHECK` → `MODIFY COLUMN` → `ADD CONSTRAINT` → `ADD COLUMN`；新增列用 `AFTER {column}` 定位。

```sql
ALTER TABLE `eo_product_report`
    DROP CHECK `chk_eo_product_report_status`,
    MODIFY COLUMN `status` TINYINT NOT NULL DEFAULT 0 COMMENT '...',
    ADD CONSTRAINT `chk_eo_product_report_status` CHECK (`status` IN (0, 1, 2, 3)),
    ADD COLUMN `reason_type` TINYINT DEFAULT NULL COMMENT '...' AFTER `reason`;
```

> **CHECK 约束值必须与字段 COMMENT 一致**——调用方可能按 COMMENT 判断，两者冲突等于埋雷。

## 四、DML 编写规范

所有 DML 必须包 `START TRANSACTION;` … `COMMIT;`。用 MySQL 8.0.20+ 推荐的 `AS new` 别名语法：

```sql
INSERT INTO `eo_category` (`id`, `name`, `sort_order`) VALUES (1, '电子数码', 1)
AS new
ON DUPLICATE KEY UPDATE `name` = new.`name`, `sort_order` = new.`sort_order`;
```

> 已弃用的 `VALUES()` 函数（`ON DUPLICATE KEY UPDATE name = VALUES(name)`）不要再用。

## 五、Flyway 配置

```yaml
# application.yaml（基础）
spring:
  flyway:
    enabled: true
    locations: classpath:db/migration
    baseline-on-migrate: true
    baseline-version: 0
    validate-on-migrate: true
    clean-disabled: true          # 生产禁止 clean
    table: flyway_schema_history
    placeholder-replacement: false
    out-of-order: false
    ignore-migration-patterns: '*:ignored'

# application-dev.yaml（开发）
spring:
  flyway:
    locations: classpath:db/migration,classpath:db/dev
    validate-on-migrate: false    # 开发阶段关闭校验，避免改 V1 后启动被 checksum 挡住
```

IT profile 复用开发者持久 dev 库，同样关 `validate-on-migrate`（迁移校验归干净库 / CI 承担）。

## 六、常用命令

| 命令 | 说明 |
|------|------|
| `mvn flyway:info` | 查看迁移状态、待执行迁移 |
| `mvn flyway:migrate` | 执行迁移 |
| `mvn flyway:validate` | 校验 checksum（CI/CD） |
| `mvn flyway:repair` | 修复历史 checksum 不匹配（谨慎） |
| `mvn flyway:clean` | 清空数据库（仅开发） |

**开发环境重置**（改了 V1 又想刷新 schema 时）：

```sql
DROP DATABASE easyorange;  CREATE DATABASE easyorange;   -- 重跑应用即从头执行 V1
```

> dev 已配 `validate-on-migrate: false`，启动不会因 checksum 不匹配崩溃——不必每次改 V1 都重置。

## 七、反模式（禁止）

| 反模式 | 问题 | 正确做法 |
|--------|------|---------|
| 修改已部署的 V 迁移 | checksum 不匹配，生产执行失败 | 新增迁移文件 |
| DDL 和 DML 混合 | 难以回滚、事务过长 | 分离 V / R 前缀文件 |
| 按"索引层"拆分 | 每次新表都要改旧文件 | 一个功能一个自包含文件 |
| NOT NULL 无默认值 | 锁表、重写所有行 | 先加 nullable → backfill → 再加约束 |
| 生产执行 clean | 数据丢失 | 保持 `clean-disabled: true` |
| 对齐列格式 | 1064 语法错误 | 紧凑格式 |
| 1 起点的枚举码列给 `DEFAULT 0` | 落非法码，读侧枚举转换抛异常（历史事故见 DATABASE.md） | 不给默认值或用合法码 + `chk_` 约束钉死 |
| 缺通用审计字段 | 无法追踪数据变更来源 | `create_by` / `update_by` / `del_flag` / `version` 为必选 |

> 表结构层面的规范（主键 `VARCHAR(36)` 应用层生成 UUID v7、`utf8mb4_0900_ai_ci`、金额 `DECIMAL(10,2)`、**禁止物理外键**、索引/约束命名）见 [DATABASE.md](../DATABASE.md)。
