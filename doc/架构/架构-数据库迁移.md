# EasyOrange 数据库迁移规范

> 本文档定义了 EasyOrange 项目的 Flyway 数据库迁移规范。
> 
> **注意**：详细的表结构定义请参考 [DATABASE.md](../../DATABASE.md)。

---

## 一、核心原则

| 原则 | 说明 |
|------|------|
| **DDL 与 DML 分离** | Schema 变更（DDL）和参考数据（DML）必须分开成独立的迁移文件 |
| **迁移不可变** | 已部署到生产环境的 V 版本迁移文件禁止修改，只能新增迁移 |
| **自包含迁移** | 每个 DDL 迁移文件包含该功能所需的完整结构（建表、索引、约束） |
| **功能驱动命名** | 一个功能一个迁移文件，不按"索引层"、"约束层"拆分 |
| **可重复数据** | 参考数据（种子数据）使用 R__ 可重复迁移，支持独立更新 |

---

## 二、迁移文件结构

```
db/migration/
├── V1__init_schema.sql              # DDL: 初始表结构（全部 CREATE TABLE，含索引、约束）
├── V2__{feature_name}.sql           # DDL: 后续 Schema 变更（ALTER TABLE）
├── V3__{feature_name}.sql           # DDL: 后续 Schema 变更
├── R__seed_{domain}.sql             # DML: 参考数据（可重复执行，按业务域拆分）
├── R__seed_{domain}.sql             # DML: 参考数据（可重复执行）
└── ...                              # 持续追加

db/dev/
└── R__insert_dev_test_data.sql      # DML: 开发测试数据（仅开发环境）
```

### DDL 文件（V 前缀）

| 文件 | 职责 |
|------|------|
| `V1__init_schema.sql` | 所有初始 CREATE TABLE，含索引、约束、注释 |
| `V{N}__feature.sql` | 后续版本的功能性 DDL 变更（ALTER TABLE、CREATE TABLE） |

### DML 文件（R 前缀）

| 文件 | 职责 | 特点 |
|------|------|------|
| `R__seed_{domain}.sql` | 业务参考数据（分类、支付渠道、消息模板等） | 可重复执行，每次变更 checksum 后自动重跑 |
| `R__insert_dev_test_data.sql` | 开发测试数据 | 放在 `db/dev/`，仅 dev 环境加载 |

---

## 三、命名规范

| 类型 | 命名模式 | 示例 |
|------|---------|------|
| DDL 迁移 | `V{N}__{feature_name}.sql` | `V2__{feature_name}.sql` |
| 参考数据 | `R__seed_{domain}.sql` | `R__seed_categories.sql` |
| DEV 测试数据 | `R__insert_dev_test_data.sql` | 放在 `db/dev/` 目录 |

### R__ 可重复迁移使用原则

- **适用场景**：参考数据（分类、配置、模板等业务基础数据）
- **幂等要求**：必须使用 `ON DUPLICATE KEY UPDATE` 保证幂等
- **事务包裹**：必须包裹在 `START TRANSACTION` / `COMMIT` 中
- **独立按域拆分**：一个业务域一个文件（分类 / 支付配置 / 消息模板...）
- **频繁更新的 DML** 优先使用 R__，避免创建大量空版本号

## 四、DDL 编写规范

**索引和约束内联定义：**

```sql
CREATE TABLE `eo_product_review` (
    `id` VARCHAR(36) NOT NULL COMMENT '主键 ID',
    `product_id` VARCHAR(36) NOT NULL COMMENT '商品 ID',
    `user_id` VARCHAR(36) NOT NULL COMMENT '评价用户 ID',
    `rating` TINYINT NOT NULL DEFAULT 5 COMMENT '评分（1-5）',
    `content` TEXT NOT NULL COMMENT '评价内容',
    `status` TINYINT NOT NULL DEFAULT 1 COMMENT '状态（0 隐藏 1 显示 2 待审核）',
    `create_time` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    `update_time` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    `del_flag` TINYINT NOT NULL DEFAULT 0 COMMENT '删除标志（0 正常 2 删除）',
    `version` INT NOT NULL DEFAULT 0 COMMENT '乐观锁版本号',
    PRIMARY KEY (`id`),
    KEY `idx_eo_product_review_product_id` (`product_id`),
    KEY `idx_eo_product_review_user_id` (`user_id`),
    KEY `idx_eo_product_review_create_time` (`create_time` DESC),
    CONSTRAINT `chk_eo_product_review_rating` CHECK (`rating` >= 1 AND `rating` <= 5),
    CONSTRAINT `chk_eo_product_review_status` CHECK (`status` IN (0, 1, 2))
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci COMMENT='商品评价表';
```

### ALTER TABLE 规范

- **合并操作**：同一张表的多个 ALTER 合并为一条 `ALTER TABLE` 语句
- **操作顺序**：`DROP CHECK` → `MODIFY COLUMN` → `ADD CONSTRAINT` → `ADD COLUMN`
- **AFTER 定位**：新增列使用 `AFTER {column}` 指定位置

```sql
ALTER TABLE `eo_product_report`
    DROP CHECK `chk_eo_product_report_status`,
    MODIFY COLUMN `status` TINYINT NOT NULL DEFAULT 0 COMMENT '...',
    ADD CONSTRAINT `chk_eo_product_report_status` CHECK (`status` IN (0, 1, 2, 3)),
    ADD COLUMN `reason_type` TINYINT DEFAULT NULL COMMENT '...' AFTER `reason`;
```

## 五、DML 编写规范

**事务包裹（所有 DML 必须）：**

```sql
START TRANSACTION;

-- INSERT 语句 ...

COMMIT;
```

**使用 MySQL 8.0.20+ 推荐的别名语法：**

```sql
-- GOOD: 使用 AS new 别名（MySQL 8.0.20+）
INSERT INTO `eo_category` (`id`, `name`, `parent_id`, `level`, `sort_order`, `status`)
VALUES (1, '电子数码', 0, 1, 1, 1)
AS new
ON DUPLICATE KEY UPDATE
    `name` = new.`name`,
    `sort_order` = new.`sort_order`,
    `update_time` = NOW();

-- BAD: 使用已弃用的 VALUES() 函数（MySQL 8.0.20+ 弃用）
INSERT INTO `eo_category` (`id`, `name`, `parent_id`, `level`, `sort_order`, `status`)
VALUES (1, '电子数码', 0, 1, 1, 1)
ON DUPLICATE KEY UPDATE
    `name` = VALUES(`name`);  -- 已弃用
```

## 六、Flyway 配置规范

**application.yaml（基础配置）：**

```yaml
spring:
  flyway:
    enabled: true
    locations: classpath:db/migration
    baseline-on-migrate: true
    baseline-version: 0
    validate-on-migrate: true
    clean-disabled: true
    table: flyway_schema_history
    placeholder-replacement: false
    out-of-order: false
    ignore-migration-patterns: '*:ignored'
```

**application-dev.yaml（开发环境）：**

```yaml
spring:
  flyway:
    locations: classpath:db/migration,classpath:db/dev
    out-of-order: true         # 开发环境允许乱序，便于团队协作
```

## 七、常用命令

| 命令 | 说明 | 使用场景 |
|------|------|---------|
| `mvn flyway:info` | 查看迁移状态 | 检查当前版本、待执行迁移 |
| `mvn flyway:migrate` | 执行迁移 | 应用新迁移 |
| `mvn flyway:validate` | 校验迁移 | CI/CD 中验证 checksum |
| `mvn flyway:repair` | 修复历史 | 修复 checksum 不匹配（谨慎使用） |
| `mvn flyway:clean` | 清空数据库 | 仅开发环境使用 |

**开发环境重置：**

当 DDL 文件被修改后（开发阶段允许），需重置 Flyway 状态：

```sql
TRUNCATE flyway_schema_history;
-- 然后重新执行 mvn flyway:migrate
```

## 八、反模式（禁止）

| 反模式 | 问题 | 正确做法 |
|--------|------|---------|
| 修改已部署的 V 迁移 | 导致 checksum 不匹配，生产环境执行失败 | 新增迁移文件 |
| DDL 和 DML 混合 | 难以回滚，事务过长 | 分离成独立文件（V 前缀 DDL，R 前缀 DML） |
| 按"索引层"拆分 | 每次新表都要改已存在的文件 | 每个功能自包含 |
| NOT NULL 无默认值 | 锁表，重写所有行 | 先加 nullable，backfill 后再加约束 |
| 生产环境执行 clean | 数据丢失 | `clean-disabled: true` |
| **对齐列格式**（列名与类型间大量填充空格） | **Flyway MySQL 解析器可能异常处理，导致 1064 语法错误** | **统一使用紧凑格式，与其他表风格一致** |
| CHECK 约束与字段 COMMENT 不一致 | 约束和业务注释冲突，调用方按 constaint 判断但注释错误 | DDL 中 CHECK 约束值必须与 COMMENT 描述一致 |
| 独立表缺少通用审计字段 | 无法追踪数据变更来源 | `create_by`/`update_by`/`del_flag`/`version` 作为必选字段 |

## 九、表结构设计规范

| 规范 | 说明 |
|------|------|
| 主键 | 使用 `VARCHAR(36)`，禁止自增，由应用层生成（UUID v7） |
| 字符集 | 统一使用 `utf8mb4`，排序规则 `utf8mb4_0900_ai_ci` |
| 时间字段 | `create_time`、`update_time` 必须有默认值 |
| 软删除 | `del_flag` TINYINT，0 正常，2 删除 |
| 乐观锁 | `version` INT，默认 0 |
| 审计字段 | `create_by`、`update_by` VARCHAR(36) |
| 索引命名 | `idx_{table}_{columns}` 或 `uk_{table}_{columns}`（唯一索引） |
| 约束命名 | `chk_{table}_{column}`（CHECK 约束） |
| 外键 | 禁止使用物理外键，通过应用层维护关联 |
