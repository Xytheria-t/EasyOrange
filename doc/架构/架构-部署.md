## 一、配置分层

| 配置文件 | 用途 | 覆盖内容 |
|---------|------|---------|
| `application.yaml` | 基础配置 | 数据源、Redis、MyBatis-Plus、通用安全配置、虚拟线程、Micrometer Tracing |
| `application-dev.yaml` | 开发环境 | 较小连接池、Flyway 开发数据、JWT 开发密钥、详细日志 |
| `application-prod.yaml` | 生产环境 | 大连接池、SSL、严格安全、JSON 日志、Swagger 禁用 |

**敏感配置**：`JWT_RSA_PRIVATE_KEY` / `_PUBLIC_KEY`、`EASYORANGE_DB_PASSWORD`、`REDIS_PASSWORD`、`RABBITMQ_PASSWORD`、`CORS_ALLOWED_ORIGINS` 生产环境必须经环境变量注入且无默认值；禁止在代码或配置文件硬编码密钥。prod 下 `ProdSecrets`（`@ConfigurationProperties` + `@Validated` + `@NotBlank`）缺失即中止启动。全量键位见仓库根 `.env.example`（说明见 [easyorange-backend/AGENTS.md](../../easyorange-backend/AGENTS.md)「构建 / 启动 / 环境」）。

### JVM 与运行时

```bash
JAVA_OPTS="-Xms256m -Xmx2g -XX:+UseG1GC -XX:+UseStringDeduplication"
SPRING_PROFILES_ACTIVE=prod
```

| 参数 | 说明 |
|------|------|
| `-XX:+UseG1GC` | G1（JDK 25 默认，容器内显式声明） |
| `-XX:+UseStringDeduplication` | G1 字符串去重，省堆 |
| 优雅停机 | `server.shutdown=graceful`，超时 90s |

### compose.yaml 开发环境

```bash
docker compose -f compose.yaml up -d                      # MySQL + Redis + RabbitMQ
docker compose --profile search up -d elasticsearch        # dev 默认启用检索，起后端前必须先起 ES
```

中间件连接参数由显式 env 直连（不用 `@ServiceConnection` 自动发现），凭据与端口统一 `${VAR:-default}` 经仓库根 `.env` 插值——无 `.env` 也能零配置启动；`MYSQL_USER/MYSQL_PASSWORD` 与应用的 `EASYORANGE_DB_USERNAME/_PASSWORD` 同源。k8s overlay 的 `*.env.example` 同口径标注「必须一致」。

### Docker 多阶段构建

```bash
cd easyorange-backend && DOCKER_BUILDKIT=1 docker build -f Dockerfile -t easyorange-backend:latest .
```

两阶段构建（builder JDK → runtime JRE）；非 root 用户 `easyorange:easyorange` 运行；健康检查用 Alpine 自带 wget；时区 `Asia/Shanghai`。

## 二、Kubernetes 部署（kustomize）

> **定位**：K8s 只编排**无状态应用层**（backend + frontend）。本地开发与集成测试继续走 docker compose（`*IT` 依赖 compose 栈），两者互不替代。

```
k8s/
├── base/                    # Deployment/Service/HPA/PDB/PVC/Ingress/NetworkPolicy/ConfigMap
├── overlays/demo/           # k3s 单机自包含演示（含 MySQL/Redis/RabbitMQ StatefulSet，demo-only）
├── observability/           # ServiceMonitor + PrometheusRule（需 kube-prometheus-stack）
└── scripts/                 # JWT 密钥生成
```

**实践要点**：

- **零中断滚动**：`maxUnavailable=0` + `maxSurge=1` + 优雅停机（`terminationGracePeriodSeconds=120`）
- **探针三件套**：startup=`/actuator/health` / readiness=`/actuator/health/readiness`（db/redis/rabbit/ai 就绪组）/ liveness=`/actuator/health/liveness`（仅 JVM）
- **HPA**：CPU 70% 基准 2→6 副本（Java 内存不进 HPA，GC 会掩盖真实压力）
- **最小权限**：非 root（backend 1000 / nginx 101）+ drop ALL cap + seccomp RuntimeDefault + 只读根文件系统 + `automountServiceAccountToken=false`；PDB `minAvailable=1`；命名空间 baseline
- **零信任网络**：默认拒绝 + 显式放行（NetworkPolicy；k3s flannel 不强制，Cilium/kube-router 下自动生效）
- **配置分层**：非敏感→ConfigMap；敏感→kustomize secretGenerator（内容 gitignore，模板 `*.example`）；JWT RSA PEM→Secret 只读挂载
- **可观测性**：`k8s/observability`（ServiceMonitor 抓 `/actuator/prometheus` + Down/5xx/P99 告警）

```bash
bash easyorange-backend/keys/generate-rsa-keypair.sh k8s/overlays/demo/env/jwt
kubectl apply -k k8s/overlays/demo
```

完整步骤 + 生产演进清单（托管中间件 / TLS / ExternalSecret / RWX 存储 / GitOps）见 [k8s/README.md](../../k8s/README.md)。

## 三、已评估暂缓的演进

**common 模块拆分**（`common-tech` / `common-domain`）：暂缓。30 个源文件中仅 3 个真正属于 domain 类（`Money` / `DomainEvent` / `DomainEventPublisher`），且 `Money` 依赖 `BizRequire`（技术工具），拆完 domain 侧反而违反「无框架依赖」；100+ 处导入需审查、10+ 模块 pom 需改，收益低于成本。**重新评估时机**：domain 类增长到 10+ 个，或出现明确反模式。
