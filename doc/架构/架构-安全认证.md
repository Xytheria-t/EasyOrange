# EasyOrange 安全认证架构

> 本文档定义了 EasyOrange 项目的安全认证架构和配置要点。

---

## 一、认证流程

```
客户端                     服务端
  │                         │
│  POST /api/auth/login   │
│  {identifier, password} │
  │────────────────────────►│
   │                         │  AuthAppService → AuthenticationService
   │                         │  验证密码（PasswordEncoderPort）
   │                         │  检查登录安全（LoginSecurityService）
   │                         │  TokenService.createAccessToken() + createRefreshToken()
   │                         │  → Access = RSA 签名 JWT；Refresh = opaque 落 Redis（SHA-256 哈希）
   │                         │  → RefreshCookie 写 HttpOnly Cookie（eo_refresh_token）
   │  {accessToken, user} + Set-Cookie │
   │◄────────────────────────│
   │                         │
   │  GET /api/users/me      │
   │  Authorization: Bearer xxx │
   │────────────────────────►│
   │                         │  SecurityConfig.oauth2ResourceServer()
   │                         │  → JwtDecoder 验证签名 + issuer 检查（RSA 公钥）
   │                         │  → JwtAuthenticationConverter 构造 AuthUser
   │                         │  → 设置 SecurityContext
   │                         │  → TokenRevocationFilter 黑名单 + 强制登出检查
   │                         │  → 继续过滤器链
   │  {user data}            │
   │◄────────────────────────│
  │                         │
  │  POST /api/auth/refresh │
  │  (自动携带 eo_refresh_token cookie) │
  │────────────────────────►│
  │                         │  RefreshCsrfFilter 校验 X-Client-Type 头
  │                         │  TokenService.rotateRefreshToken()
  │                         │  → opaque 轮换（复用检测 / 30s 宽限期 / 盗用吊销）
  │                         │  → 查库校验用户存在 + 启用
  │                         │  → 签发新 access（RSA JWT）
  │  {accessToken} + 新 Set-Cookie │
  │◄────────────────────────│
```

## 二、安全配置要点

| 配置项 | 说明 |
|--------|------|
| 认证方式 | access = RSA 签名 JWT（无状态，`oauth2ResourceServer` 校验）；refresh = opaque 存 Redis，HttpOnly Cookie 传输，JS 不可见 |
| Token 类型 | Access Token（RSA JWT，30 分钟）+ Opaque Refresh Token（7 天，落 Redis 存 SHA-256 哈希），刷新时轮换 + 复用检测；仅登出时将 access jti 加入 Redis 黑名单 |
| CSRF 防护 | `RefreshCsrfFilter` 对 refresh/logout 强制要求自定义头 `X-Client-Type`（`csrfProtectedPaths` 配置驱动） |
| 密码存储 | BCrypt 哈希，由 `PasswordEncoderPort` 抽象 |
| CORS | 通过 `security.allowed-origins` 配置白名单 |
| XSS 防护 | `Content-Security-Policy` 头 (`default-src 'none'`)，`X-XSS-Protection` 已禁用（已废弃） |
| 限流 | `RateLimitFilter` 配置驱动（GET 本地限流，写操作 Redis 分布式限流） |
| 防重复提交 | `RateLimitFilter` 约定式拦截写操作（Redis SETNX，3秒间隔） |
| 安全路径放行 | 登录/注册/密码重置/健康检查/公开商品浏览等 |

## 三、安全路径分类

| 路径类别 | 说明 | 示例 |
|---------|------|------|
| `ignore-paths` | 完全跳过安全过滤器 | `/api/auth/login`, `/api/health` |
| `product-paths` | 商品浏览（公开只读） | `/api/products`, `/api/products/search` |
| `static-paths` | 静态资源 | `/static/**`, `/upload/**` |

### ⚠️ `product-paths` 配置陷阱

`product-paths` 中的路径会跳过 JWT 认证（`SecurityConfig` 的 `.requestMatchers(GET, path)` 配置），匹配规则为：
- 精确匹配：`/api/products` 匹配 `/api/products`
- 前缀匹配：`/api/products` **也会匹配 `/api/products/my`**

这意味着如果配置 `/api/products` 作为公开路径，**所有以 `/api/products/` 开头的 GET 请求都会被公开访问**，包括需要认证的接口（如 `/api/products/my`）。

**解决方案**：
1. 在 `SecurityConfig` 中添加更精确的 `.requestMatchers(GET, "/api/products/my/**").authenticated()` 覆盖公开匹配
2. 或改用更精确的路径配置（如 `/api/products/search` 而非 `/api/products`）

## 四、登录错误消息规范（OWASP）

**CRITICAL**: 登录失败统一返回"用户名或密码错误"，防止用户枚举攻击。

```java
// BAD — 泄露用户存在性
User user = userRepository.findByUsername(username)
    .orElseThrow(() -> new UserNotFoundException("用户不存在"));  // 攻击者可枚举用户名

if (!passwordMatches(password, user.getPassword())) {
    throw new InvalidPasswordException("密码错误");  // 攻击者知道用户存在
}

// GOOD — 统一错误消息
User user = userRepository.findByLoginIdentifier(identifier).orElse(null);

if (user == null || !passwordMatches(password, user.getPassword())) {
    throw new AuthenticationException("用户名或密码错误");  // 统一错误，无法枚举
}

// 用户状态检查可以在认证通过后进行
if (!user.isActive()) {
    throw new AccountDisabledException("账号已禁用");  // 业务状态，用户应知道
}
```

| 场景 | 返回错误 | 原因 |
|------|---------|------|
| 用户不存在 | "用户名或密码错误" | 防止攻击者枚举用户名 |
| 密码错误 | "用户名或密码错误" | 与用户不存在保持一致 |
| 用户禁用 | "账号已禁用" | 业务状态，用户应知道原因 |

**Reference**: [OWASP Authentication Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html#incorrect-and-correct-response-examples)
