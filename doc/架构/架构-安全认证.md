# EasyOrange 安全认证

> 双 Token 的完整流程、配置项与安全约定。JWT 实现细节（`TokenService` / 过滤器顺序）见 [easyorange-framework/AGENTS.md](../../easyorange-backend/easyorange-framework/AGENTS.md)；配置键见 [CONFIGURATION.md](../../easyorange-backend/easyorange-framework/CONFIGURATION.md)。

---

## 一、认证流程

**登录**：`POST /api/auth/login` → `AuthAppService` → `AuthenticationService`（`PasswordEncoderPort` 校验 + `LoginSecurityService` 检查）→ `TokenService` 签发：

- **Access** = RSA 签名 JWT（30min，无状态，前端内存持有）
- **Refresh** = opaque 随机串，Redis 只存 SHA-256 哈希（7 天），经 HttpOnly Cookie `eo_refresh_token` 下发，JS 不可见

**业务请求**：`Authorization: Bearer xxx` → `SecurityConfig.oauth2ResourceServer()` → `JwtDecoder` 验签 + issuer 检查 → `JwtAuthenticationConverter` 构造 `AuthUser` → `TokenRevocationFilter` 黑名单/强制登出检查（仅登出时把 access jti 加入 Redis 黑名单）。

**刷新**：`POST /api/auth/refresh`（自动携带 Cookie）→ `RefreshCsrfFilter` 校验 `X-Client-Type` 头 → `TokenService.rotateRefreshToken()` 轮换（复用检测 / 30s 宽限期 / 盗用即吊销）→ 查库校验用户存在且启用 → 签发新 access。

## 二、安全配置要点

| 配置项 | 说明 |
|--------|------|
| 认证方式 | access = RSA JWT（无状态校验）；refresh = opaque 存 Redis，HttpOnly Cookie 传输 |
| Token 生命周期 | Access 30min + Refresh 7 天（存 SHA-256 哈希），刷新时轮换 + 复用检测 |
| CSRF 防护 | `RefreshCsrfFilter` 对 refresh/logout 强制要求 `X-Client-Type` 头（`csrfProtectedPaths` 配置驱动） |
| 密码存储 | BCrypt，由 `PasswordEncoderPort` 抽象，强度 12（可配 4-31） |
| CORS | `security.allowed-origins` 白名单 |
| XSS 防护 | CSP `default-src 'none'`；`X-XSS-Protection` 已禁用（浏览器废弃） |
| 限流 / 防重 | `RateLimitFilter`：GET 本地限流、写操作 Redis 分布式令牌桶、3s 防连点 |
| 幂等 | `IdempotencyKeyFilter`：`Idempotency-Key` 头 + 24h 响应缓存，非 2xx 不缓存 |
| 安全路径放行 | 登录/注册/密码重置/健康检查/公开商品浏览 |

### ⚠️ `product-paths` 前缀匹配陷阱

`security.product-paths` 里的路径会**跳过 JWT 认证**，且匹配是**前缀**语义——配了 `/api/products`，`/api/products/my` 这类需要认证的接口也会被公开。

修法（二选一）：① 在 `SecurityConfig` 补更精确的 `.requestMatchers(GET, "/api/products/my/**").authenticated()` 覆盖；② 收敛配置为更精确的路径（如 `/api/products/search`）而非 `/api/products`。

### 登录错误消息规范（OWASP）

**登录失败统一返回「用户名或密码错误」**，防止用户枚举：用户不存在与密码错误必须同文案（否则攻击者能枚举用户名）；账号禁用属业务状态，可单独提示「账号已禁用」。

```java
User user = userRepository.findByLoginIdentifier(identifier).orElse(null);
if (user == null || !passwordMatches(password, user.getPassword())) {
    throw new AuthenticationException("用户名或密码错误");   // 统一文案，不可枚举
}
if (!user.isActive()) {
    throw new AccountDisabledException("账号已禁用");        // 业务状态，用户应知道
}
```

> 参考 [OWASP Authentication Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html#incorrect-and-correct-response-examples)。

## 三、其它已落地的数据与安全约束

| 约束 | 实现位置 |
|------|---------|
| Access Token 不入日志、不入本地存储 | 前端内存持有 + Refresh 走 HttpOnly Cookie |
| PII 视图层脱敏（手机号 / 地址） | `MaskUtils` + 各模块 assembler |
| 审计日志脱敏：不写密码 / 令牌 / 完整手机号 | `AuditLogAspect#maskSensitiveFields` |
| 生产密钥经环境变量注入且 fail-fast | `ProdSecrets`（缺失或为空即中止启动） |
| 管理端接口仅 ADMIN 可访问 | `SecurityConfig` 路径规则 `/api/admin/**` → `hasRole("ADMIN")`；product / payment 敏感端点另有 `@PreAuthorize` |
