# EasyOrange 模拟面试题库（面试版）

> **用途**：面试前找人模拟或自测用的完整题库——按岗位两条完整追问链 + 通用题库 + HR/行为面。每条追问链模拟真实面试「问题 → 追问 → 深挖」的节奏。
>
> **用法**：让朋友/自己按题号逐条问，答完对照「参考答案位置」自查。目标：**每条主线能答到第 3 层追问不崩**。
>
> 版本：v1.0 · 2026-08-08

## 二、Java 架构师 / 高级后端 — 完整追问链（10 问）

**Q1** 自我介绍（1 分钟）
→ 参考：话术集 §2.1

**Q2** 11 个模块怎么解耦的？跨模块通信有哪些方式？
→ 参考：走读指南 §10（Port 归调用方 + Adapter 归 application + optional 隔离 + 写事件化/读同步化）
追问 2.1：为什么查询保留同步调用不也走事件？
→ 参考：延迟 + 最终一致窗口 + 无消息积压负担（ADR-0006）

**Q3** 下单链路讲一下？为什么拒绝 Saga？
→ 参考：走读指南 §1 + 话术集 §2.2（本地事务 + 锁 + Outbox；Saga 补偿与回滚重复/状态丢失）
追问 3.1：锁和事务的顺序？锁过期怎么办？
→ 参考：走读指南 §1 追问 + §4（锁在事务内 + isHeldByCurrentThread + 10s 租约）
追问 3.2：什么时候才会上 Saga？
→ 参考：ADR-0007 触发条件（product/payment 拆独立数据源/独立部署）

**Q4** Outbox 怎么保证事务一致的？崩溃了真不丢吗？
→ 参考：话术集 §2.2（同事务双写 EVENT_PUBLICATION + 提交后异步外发 + completion_date + 重启重发）

**Q5** 消息不丢不重怎么保证？
→ 参考：速答 §六-27/28（Outbox + 手动 ack + DLQ 三级重试 + EventIdempotencyChecker 锁内查-写）

**Q6** 为什么用 RabbitMQ 不用 Kafka？
→ 参考：话术集 §2.2（4 维度评分：DLQ 声明式/模型匹配/成本/运维）

**Q7** ArchUnit 守了什么？CI 真的能阻断吗？
→ 参考：话术集 §2.2（10 条规则 + GitHub Actions build-and-test 红闸门）

**Q8** 缓存怎么做的？击穿/穿透/雪崩？
→ 参考：走读指南 §9（MultiLevelCache 三防 + TTL 配平 + Pub/Sub 广播 + 指标）
追问 8.1：布隆过滤器为什么删了？
→ 参考：速答 §五-22（负缓存 30s 已覆盖穿透，Bloom 是过度设计——拒绝过程加分）

**Q9** traceId 怎么全链路传递的？
→ 参考：速答 §七-38（HTTP → MDC → @Async → MQ header → 消费者 MDC；拆多 JVM 走 W3C traceparent）

**Q10** 测试怎么保证质量？（JaCoCo + PIT 双门禁）
→ 参考：话术集 §2.2（行覆盖只测执行过，PIT 变异测「测试能否发现缺陷」+ order 模块 70%/89% 实测 + ArchUnit 无白名单）
追问 10.1：PIT 全量跑多久？CI 跑得起吗？
→ 参考：面试指南 §五（domain 层 nightly 3-5 分钟，PR 只跑 JaCoCo + ArchUnit）

## 四、行为面 / HR 面（8 题）

> HR 面不是技术面——**每个答案控制在 1-2 分钟，用 STAR 结构**（情境-任务-行动-结果），结果要有数字。

**H1 自我介绍（HR 版，30 秒）**
→ 参考：面试指南 §3.1（开场抛钩子：LLM × DDD 双岗位叙事 + 2,400+ 测试/84.1% 覆盖）

**H2 为什么做这个项目？**
→ STAR：看到「AI 应用工程化落地难」的普遍痛点 → 自己定义两条主线（AI 工程化 + DDD 架构）→ 单人完成 11 模块后端 + 前端 → 2,400+ 测试 + 9 条 ADR 决策记录 + 压测 640 QPS。**不要**说「为了找工作」——说「用生产标准自证工程能力」。

**H3 项目遇到的最大困难？**
→ 推荐叙事（选一）：
- 技术选型推翻重来：自研 AI 抽象 → Spring AI 2.0 GA 后全面框架化（ADR-0003 → 0008）——「承认判断失误 + 记录决策翻转」是成熟工程师的标志
- 或：Saga 上线后回退（ADR-0001 → 0007）
- 或：Redis 序列化器坑（限流器 fail-open 排查链）

**H4 怎么评价自己的技术能力/短板？**
→ 先说强项（架构决策 + 工程化规范 + 测试意识），短板说一个**真实的且正在补的**：「Spring AI 框架源码级细节我还没吃透（Bean 注册/FunctionCallback 内部），已经在读源码 + 计划写深入笔记」——诚实 + 行动闭环。

**H5 为什么离开现在的公司/换方向？**
→ 目标导向：技术深度追求 + 想在大模型 × 工程化的交叉方向深耕（结合项目叙事），不贬低前东家。

**H6 期望薪资？**
→ 报区间不报点：区间下限 = 可接受底线，上限 = 市场合理值；先反问对方职级带宽再报价。「我看重的是这个岗位的技术方向，薪资在贵司标准内希望匹配我的经验」。

**H7 你还有什么想问的？（必准备）**
→ 技术向（展示深度，反问面试官）：
- 「你们团队 AI 工程化目前怎么处理 LLM 降级和成本控制的？」
- 「用 DDD 的话你们怎么守 domain 层零框架依赖？ArchUnit 还是 code review？」
- 「事件驱动链路怎么保证不丢消息？有 Outbox 吗？」
- 别问：公司技术栈是什么/加班多吗/有食堂吗（初面）

**H8 多久能到岗 / 为什么选我们公司？**
→ 提前查公司官网 + JD，说 1-2 个具体匹配点（技术栈/方向/团队），显示做过功课。
